# ADR-0060 插槽一览：核心登记每个插槽在哪个页面，文档站按登记的插槽自动截图，用黑框和序号标出位置

- 状态：已采纳
- 日期：2026-10-23
- 补充 ADR-0054：文档站多了一类由仓库代码生成、提交进仓库的内容
- 补充 ADR-0059：插槽多了一张核心的登记表

## 背景

ADR-0059 开了两个插槽。作者文档里，插槽的位置只有半句话（"公告下面"、"站点的几个数字下面"），没有图。作者想知道挂件放出来在页面的哪里、是什么样，只能自己搭站点、写插件试。以后插槽多了（挂在对象上的、给运行时组件的），半句话更说不清。

现状：
- 插槽的名字写在三处：SDK 的 `SlotName`（类型）、plugin host 的 `widgetSlots`（插槽 → 区域，校验链接用）、`apps/web/lib/plugin-widgets.ts` 的 `SLOT_AREA`（同一张表，筛挂件用）。后两处用 `satisfies Record<SlotName, …>` 跟着类型，漏写编译不过。插槽在哪个页面，只写在页面的代码和文档的文字里。
- 页面上看不出哪块是插槽；没有挂件时 `PluginWidgets` 什么也不渲染。
- 文档站（ADR-0054）的插件 API 参考由 `scripts/sync.ts` 从 `packages/plugin-sdk/docs` 生成，没有图片。图片原样发布（`passthroughImageService`，不装 sharp）。文档站只在正式版发布后部署。
- 截图要用的都有：e2e 从 `dist/nextskin` 经启动器起服务、写入契约用例的固定数据；组件截图（`test:visual`）的浏览器跑在 Playwright 官方镜像里，挂载固定的中文字体，谁来跑结果都一样。`pnpm design:sync` 是"本地运行、生成的文件提交进仓库"的先例。

要定的：插槽登记在哪、页面上怎么找到插槽、截什么、怎么标、图放在哪和什么时候生成、怎么发现图过期。

## 决定

### 登记表

plugin host 的 `widgetSlots` 改名 `pluginSlots`，挪到单独的文件 `packages/plugin-host/src/slots.ts`（包导出 `@nextskin/plugin-host/slots`，文档站读它不用加载整个 plugin host），每个插槽登记区域和所在页面的路径：

```ts
export const pluginSlots = {
  'user.dashboard': { area: 'user', path: '/user' },
  'admin.dashboard': { area: 'admin', path: '/admin' },
} as const satisfies Record<SlotName, { area: 'user' | 'admin'; path: string }>
```

- 插槽名的来源仍是 SDK 的 `SlotName`，这张表补上只有核心知道的事。plugin host 和安装时的 schema 照旧从这里读插槽名和区域；`SLOT_AREA` 删掉，`apps/web` 经 `@nextskin/domain` 读这张表。
- 表里的顺序就是文档里的序号；同一页面的插槽写在一起。
- 页面的名字用已有的文案 `admin.plugins.slots.<插槽>`，后台"这个插件会做什么"也用它。
- 以后挂在对象上的插槽，`path` 写路由的格式（如 `/skinlib/[tid]`）；截图时打开哪个对象，由截图脚本按固定数据决定。
- 只在核心内部，不进 SDK 的公开面：页面的路径是核心的事，挪页面不该让 SDK 发版。

### 页面上的标记

- 插槽的容器带 `data-plugin-slot="<插槽名>"`。`PluginWidgets` 多一个 `slot` 参数，标在挂件格子的外层。不用 `data-slot`：组件库常用这个名字标组件的部件。
- 没有挂件时照旧什么也不渲染，不为截图留占位。空插槽不占位置，文档里写明。
- 这个属性不对外承诺，站长的自定义 CSS 不要拿它当钩子（同 ADR-0059 对挂件 `name` 的说法）。

### 截什么

- **演示插件**：放在 `apps/docs/screenshots/demo-plugin`，只用公开 API，在每个插槽里放两个挂件，一个统计、一个 Markdown，内容说明这里是插件的挂件。两个是一个插件在一个插槽里的上限，正好显示出大屏两列、窄屏一列。新增插槽时演示插件跟着加；有插槽里没有挂件时，截图脚本报错。
- **数据**：在契约用例的固定数据上起站（有用户、角色、材质），命令行把其中一个有角色的用户设成超级管理员，用这个账号截图。启动之前直接往设置表里写站名、一条公告和邮件的发件地址（不然后台概览顶上是"还有配置没完成"）；不经后台改，免得记进审计日志、出现在后台概览的截图里。页面要像一个在用的站点，不是空站。
- **按页面截**：同一页面上的插槽画在一张图里。每个页面两张：桌面端 1280 宽、手机 390 宽。亮色模式、钻石青、默认结构、zh-CN。现在两个插槽各在一个页面，一共四张。
- **截到哪**：从页面顶端截到最下面那个插槽的下边，再多留 160px，不截插槽下面的全部内容。页面顶端让读者认出是哪一页；插槽下面的内容用不上。

### 怎么标

- 截图前往页面里插标注元素（Playwright 关掉这个页面的 CSP 检查，只在截图脚本里）：每个插槽外面一圈 3px 的黑框，离插槽 6px，不压住内容；左上角一个黑底白字的序号。框外再描一圈白边，压在深色内容上也看得见。
- 序号全文档统一，按登记表的顺序编，不是每张图从 1 编：一个序号只对应一个插槽，图里和表里对得上。
- 图上只写序号，不写插槽名：手机宽度上长名字挤在一起，也没法复制。序号和插槽名的对照在表格里。
- 只拍亮色：暗色页面上黑框看不见；插槽在两种模式下的位置一样。

### 文档站

- 截图和一份清单提交到 `apps/docs/src/assets/slots/`。清单 `slots.json` 记下每个插槽的序号、名字、路径，每张图的文件名和视口，以及生成时的 NextSkin 版本。
- 图片不放进 `packages/plugin-sdk/docs`：那个目录随 npm 包发布。
- `scripts/sync.ts` 按登记表和清单生成插件 API 参考里的"插槽一览"（`slots.mdx`，侧栏排在"界面"后面）：
  - 一张表：序号、插槽、页面、谁看得到（`user` 区域是登录了、没被封禁的用户，`admin` 区域是管理员和超级管理员）；
  - 每个页面一节：页面地址和这张图上的序号对照，桌面端和手机两个标签页（Starlight 的 Tabs，各节同步切换），图片链到原图；
  - 写明截图里的挂件来自演示插件、空插槽不占位置、截图对应的 NextSkin 版本。
- SDK 文档 `ui.md` 的"挂件"一节链到这一页。SDK 文档也随 npm 包发布，链接写文档站的完整地址，`sync.ts` 生成时改成站内路径。
- 文档站工作流的路径过滤加上登记表和中文文案。

### 生成

- `pnpm docs:screenshots`（`@nextskin/docs` 的 `screenshots`）：依赖 `pnpm build` 组装的发行目录（同 e2e），在临时数据目录上起一个服务，打包安装演示插件，截图，写清单。浏览器用 `test:visual` 的同一个镜像和字体，所以要 Docker。
- 不做像素比较：重新生成以后看一眼图，再提交。
- 新增或挪动插槽时必须重新生成，否则过不了检查（见下）。发正式版前，看一眼插槽所在的页面有没有改版，改了就重新生成。文档站只在正式版发布后部署，图对应的就是发布的那个版本。

### 检查

- `sync.ts` 比对登记表和清单：插槽的名字、路径、顺序对不上就失败，提示运行 `pnpm docs:screenshots`。`sync.ts` 是文档站 `typegen` 的一步，`pnpm check` 和文档站的构建都会跑到。
- e2e 里现有的挂件用例改成在 `[data-plugin-slot]` 里找挂件：标记被删掉，CI 就失败，不用等到下次截图。
- 截图脚本自己检查：每个登记的插槽在它的页面上都找得到标记，里面有演示插件的挂件，桌面端和手机都看得见。

## 后果

- 加一个插槽多了几步：登记表、页面上的标记、演示插件、重新截图。漏了哪一步，检查或截图会失败。
- 仓库里多了几张图（目前四张），文档站原样发布。
- 插槽所在页面的布局变了，图不会自动更新，检查也拦不住，靠发版前看一眼。图要说明的是位置，布局小改不影响。
- 重新生成要 Docker 和一次完整构建，几分钟。
- `apps/docs` 多了几个依赖：`sync.ts` 读 plugin host 的登记表和 i18n 的文案；截图脚本用 Playwright、构建命令和契约用例的固定数据。

## 考虑过的其他方案

- **截图以后用图像库画框**：多一个图像依赖，框的位置还是得从页面里取。直接在页面里画，浏览器负责排版。
- **文档站构建时现拍**：文档站的构建要多出完整构建、Docker 和起服务，PR 上改一个错字也要跑；部署工作流的失败点也多了。
- **手工截图**：没人记得更新，标注的样子也对不齐。
- **页面里留一个"显示插槽"的开关**（比如管理员加 `?slots=1`）：作者在自己的站点上也能看，但生产代码里多一条只为文档服务的路径，空插槽还得渲染占位。作者有需要时再看。
- **用参考插件代替演示插件**：只覆盖参考插件用到的插槽，新插槽得先有参考插件；参考插件的挂件按条件出现（204），截图前还要先造出条件。
- **在 CI 里做像素比较**：e2e 的浏览器不在镜像里，字体对不上；放进 `test:visual` 的任务又得先完整构建。每次改首页都要更新文档的图，代价比图过期大。
- **清单里记下页面源码的 hash，变了就失败**：同上，改一下首页就要 Docker 和完整构建。
- **亮暗各一套**：暗色上黑框看不见；Markdown 里的图片不跟着主题切换，要另写组件。
- **每张图的序号从 1 编**：现在两张图上都只有"1"，序号和插槽就对不上了。
- **在框上直接写插槽名**：手机上挤，也不能复制。
- **登记表进 SDK，作为运行时常量导出**：页面路径是核心的事，挪页面要 SDK 发版；公开面也多了一项要冻结的东西。
- **登记表放在 `apps/web`**：plugin host 和文档站都读不到。

## 落地顺序

一个 `feat/slot-screenshots` 分支，按顺序提交（ADR-0047：要分几个提交的功能）：

1. 这份 ADR；
2. 登记表、页面上的标记、e2e；
3. 演示插件、截图脚本、生成的图和清单，文档站的"插槽一览"和检查，`ui.md` 的链接，文档站的 README 和工作流。

不改 SDK 的公开 API，不加迁移。
