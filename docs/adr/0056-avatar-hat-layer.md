# ADR-0056 头像的帽子层按游戏的膨胀量立体出图，按显示密度出图

- 状态：已采纳
- 日期：2026-10-22

## 背景

ADR-0025 定下的头像（`renderHead`）是平面的：8×8 的脸上直接叠帽子层，按材质分辨率 k 出图，浏览器整数倍放大。

站长从 BS 迁过来以后，嫌头像比 BS 的平。BS 用户菜单里的头像是 `blessing/texture-renderer` 的 2D 头像（`render2dAvatar`）。它其实是正对着脸的正交投影：
- 头是 8×8×8 的盒子；
- 帽子是按 9/8 放大的盒子，中心和头重合，四周各伸出半格，盖在脸上；
- 帽子正面透明的地方，能看到帽子背面的内侧。

所以帽子上的头发、头盔会从脸的轮廓里鼓出来，看着是立体的。

这和游戏一致：帽子层每边膨胀 0.5 个标准像素。ADR-0048 的 3D 人物用的也是这个量。

## 决定

### 出图

- `renderHead(image, p)` 改画 BS 的那个正视图。输出 9p×9p，p 是脸上一格占多少个输出像素。
- 画法：
  - 脸占中间的 8p×8p，是不透明的基础层；
  - 帽子正面 (40, 8) 铺满整张图，一格是 9p/8 个像素，用 S4 的 `over` 叠在最上面；
  - 脸外面的那一圈，在帽子正面下面先垫一层帽子背面 (56, 8) 的内侧。从里面看，所以左右镜像。
- 按输出像素的中心取最近的材质像素，全用整数算，出图逐位稳定。
  - p 是奇数时，脸的左上边距是 (p − 1)/2 个像素，右下多一个；
  - 高清皮肤在 p 小于 s 时按中心取样，和 3D 人物一样。
- 帽子的侧面在正视图里是一条线，不画。
- 不分明暗，和 BS 的 2D 头像一样。
- 半透明的帽子像素按透明度叠加，和 3D 人物一致。BS 把它们画成不透明，这一点不照搬。
- 旧版 64×32 皮肤的帽子区域完全不透明时忽略帽子，照旧由 `prepareSkin` 处理。

### 分辨率和地址

- 帽子的一格是 9/8 个脸格，按材质分辨率出图再整数倍放大，帽子格子的宽窄做不到一致。所以和 3D 人物一样改成按显示需要出图：p 等于显示倍数乘设备像素比，浏览器不缩放（DESIGN.md §5 已经允许头像这样做）。帽子的格子宽窄差一个像素。
- p 取 1 到 16（`MAX_HEAD_DENSITY`），和材质倍数 s 无关，不再要求整除 s。
- 地址的形状不变，`/render/v{版本}/head/{p}/{hash}.png`，路径里的数从 k 改成 p。
- 渲染器版本升到 3。其他出图逐像素不变，但缓存按版本整批换掉，第一次请求时重新生成。
- 上传皮肤时预热四种尺寸 1x、2x 两档的 p：2、3、4、6、8、12。
- OIDC 的 `picture` 原来是 k = s，普通皮肤只有 8×8；改成 p = 16，统一 144×144，由客户端缩小显示。

### 组件

- PlayerHead 的 `size`（16、24、32、48）仍然是脸的大小，组件按脸占的方框排版。
- 出图是 size × 9/8 的图，绝对定位，四周伸出 size/16 个像素，所以有头像、没头像的行照样对齐。
  - 24px 的头像伸出 1.5px，往下取整成 1px：1x 屏上脸正好对齐方框，2x 屏上偏半个 CSS 像素。
- 父元素不要裁掉四周。现有的用法（表格行、对话框里的列表、PlayerPicker、资料页）四周都有内边距，伸出的部分不会被裁。
- `src` 改成 `(p) => 地址`。PlayerHead 去掉 `textureScale` 属性：选 p 用不到材质倍数。

### 负载

在 ARM 服务器上实测 `packages/skin/test/fixtures` 里的皮肤：

| | 普通皮肤 | 512×256 高清皮肤 |
|---|---|---|
| 32px 的头像 1x（p = 4） | 0.1–0.4 KB | 2.4 KB |
| 48px 的头像 2x（p = 12） | 0.2–0.4 KB | 7.8 KB |
| 渲染 + 编码（p = 12） | 1–2 ms | 约 5 ms |

和原来的 8×8 头像（约 0.3 KB）差不多。

## 后果

- **DESIGN.md 跟着改：** §5 写明头像的帽子层伸出方框、按显示密度出图；§6 的 PlayerHead 一行补上"父元素不要裁掉四周"。
- **头像比方框大一圈。** 48px 的头像实际占 54px，排版时旁边的间距要留出这 3px。现有用法的间距都在 8px 以上。
- **Storybook 的头像 fixtures 改成 p = 2、3、4、6、8、12**，四种尺寸的 1x、2x 都有。
- **ADR-0025 里头像那一句（k 的选法同 2D 正背面）作废。** ADR-0017 的其余结论不变：服务端出图、immutable 缓存、地址里带渲染器版本。

## 考虑过的其他方案

- **照旧叠平面的帽子层。** 站长要的就是 BS 那样的立体感。
- **照搬 BS 的 `?3d` 斜视头像。** BS 的菜单里用的不是它；斜着的立方体在 16、24px 的尺寸上看不清脸，也和 3D 人物的视角不一致。
- **把整张头像（含帽子）塞进 16、24、32、48px 的方框。** 脸只占 8/9，一格变成 1.78、2.67 这样的非整数，脸上的格子也宽窄不一。脸是头像最要紧的部分，所以让脸保持整数格、帽子伸出去。
- **方框改成 18、27、36、54px。** 每个用到头像的地方都要重新排版，没头像时的占位也要跟着加半格的内边距，24px 会出现 1.5px。
- **帽子按整数倍放大（脸一格 8 个像素，帽子一格 9 个）。** 最小的头像也要 72px 的图，16px 的头像在 1x 屏上没法显示。
