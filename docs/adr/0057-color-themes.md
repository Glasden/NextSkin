# ADR-0057 配色主题：插件以数据声明配色，核心检查对比度、生成 CSS；超级管理员在后台设默认主题和启用哪些，用户在用户中心选，选择存进账号；亮暗模式的属性改名 `data-mode`

- 状态：已采纳
- 日期：2026-10-23
- 补充 ADR-0033：开放它推迟的主题扩展点（`ui.themes`），趁 SDK 候选期加进 1.0 的公开面
- 补充 ADR-0011：声明式 UI 多一种贡献，不需要能力
- 补充 ADR-0042：做它"不做"里留给另一份 ADR 的主题切换
- 补充 ADR-0028：两个不进设置表单的设置项，由后台的主题页管理

## 背景

想一步步给插件补上改变观感的能力，先从配色主题做起：主题做进核心，插件可以提供多套主题；超级管理员在后台设默认主题、决定启用哪些；用户从启用的主题里选。

现状：
- token 的唯一来源是 `packages/ui/src/theme.css`（ADR-0012）。颜色 23 个，亮色写在 `@theme static`，暗色写在 `[data-theme='dark']`；`tokens.test.ts` 对亮暗两套各查 25 组对比度（正文 4.5:1，边框和焦点框 3:1）。
- 亮暗模式（DESIGN.md §10）：页头右上角选跟随系统、亮色或暗色，偏好按设备记在 Cookie 里；根布局 `<head>` 里的内联脚本在第一次绘制之前设好 `<html data-theme>`。`data-theme` 现在表示亮暗，theme.css 的 `dark:` 变体、`color-mode.ts`、验证码挂件、Storybook 和 e2e 都读它。
- DESIGN.md §2.3：主题是配色预设，和亮暗是两个维度，每个主题都有亮暗两套取值、都要过同一套对比度检查。附录保留了钴蓝、洋红、高对比三套：钴蓝、洋红只改强调色一组，洋红启用前要先把危险色挪开；高对比还改了边框粗细、圆角、静止时的阴影和链接样式。
- ADR-0033 推迟了主题扩展点：开放 token 会把 token 的名字冻住，而当时 token 还在变；需要时先在核心里做主题切换。
- ADR-0042 把主题切换（BS 的 `navbar_color`、`sidebar_color`）推给另一份 ADR。
- 插件 SDK 是 `1.0.0-rc.4`。候选期里公开面还能改（ADR-0035），1.0.0 之后新增扩展点是次版本，改名、删除是大版本。
- BS 的 `navbar_color`、`sidebar_color` 是站长选的 AdminLTE 配色名，用户不能选。导入器不导入，在对账报告里列出（ADR-0032），这次不变。

要定的：插件交什么、开放哪些 token、怎么检查、CSS 怎么生成和下发、用户的选择存在哪、后台和用户中心的界面、插件停用或卸载之后怎么办、和亮暗模式的属性怎么分开。

## 决定

### 范围

这次做：
- 亮暗模式的属性改名为 `data-mode`，`data-theme` 改为表示主题；
- 新包 `packages/theme`：可改的 token 清单、默认取值、推导、检查和生成 CSS；
- 核心的主题注册表：内置钻石青，加上已启用插件声明的主题；
- 设置项 `theme.default`、`theme.enabled`，后台的主题页；
- `users.theme` 和用户中心的主题页；
- SDK 的 `ui.themes`，构建命令和安装时的检查；
- 官方插件 `color-themes`（更多配色），提供钴蓝和洋红，作为这个扩展点的参考插件。

不做：
- 改结构的主题（高对比）：边框粗细、圆角、静止时的阴影、链接加下划线现在都写在组件的类里，不是 token。要先把这几处做成 token，另写 ADR。
- 只有亮色或只有暗色的主题：每个主题都要能配合亮暗切换。
- 字体、圆角、动效、背景图、标志、站点图标跟着主题变。
- 自定义 CSS：和主题是两回事，另做（ADR-0053 之后它不必再等 CSP）。
- 没登录的访客选主题：访客看站点默认，见"用户的选择"。

### 亮暗模式改名为 `data-mode`

`<html data-theme>` 改成 `<html data-mode>`，取值照旧是 `light`、`dark`；Cookie `nextskin-color-mode` 不变。要改的有：theme.css 的暗色块和 `@custom-variant dark`、`apps/web/lib/color-mode.ts` 的内联脚本、验证码挂件找暗色祖先的选择器、Storybook 的工具栏、e2e、DESIGN.md §10。`apps/docs`、`apps/site` 有各自的样式，不动。

`data-theme` 留给主题：DESIGN.md 和界面文案里的"主题"指配色，代码里也是同一个意思。运行时组件（`ui.script`）还没开放，没有插件的 CSS 依赖这个属性，现在改名代价最小；开放之后它就是公开 API 了。

### 主题的形状

主题只是数据：给出部分可改 token 在亮色、暗色下的取值。插件交的不是 CSS，核心按数据生成 CSS。

- **可改的 token**：除 `stage`、`checker-a`、`checker-b` 以外的 20 个颜色。展台和透明区域的棋盘格锁住，在任何主题下都取默认值：展台在亮暗两种模式下都取中间调，深色、浅色皮肤都看得清（DESIGN.md §2.2、原则 1）。圆角、字体、动效不开放。
- **取值**：`#rrggbb`，不分大小写，存下来一律小写。不收别的写法，生成的 CSS 里只会出现检查过的色值，不会被拼进别的东西。
- **只写要改的**：没写的 token 按下面的推导补齐，其余的取钻石青。钴蓝、洋红在附录里本来就是"除下列 token 外与钻石青相同"；作者不用抄一遍灰色，核心以后微调灰色时也会跟着变。
- **推导**：只改了强调色的主题，焦点框和淡底也要跟着换，不能残留钻石青的青色。所以主题没写这两个 token 时：
  - `focus` 等于这个主题的 `accent`；
  - `accent-subtle` 是这个主题的 `accent` 按 12%（亮色）或 16%（暗色）在 sRGB 里混入这个主题的 `surface`。

  钻石青、钴蓝、洋红在附录里的这两个值都正好是这样算出来的，测试核对钻石青推导出来的值和 theme.css 一致。
- **id**：内置主题没有斜杠（钻石青是 `diamond`），插件的主题是 `<插件 id>/<名字>`，名字是 `[a-z][a-z0-9]*(-[a-z0-9]+)*`、最多 32 个字符，同一个插件里不重复，一个插件最多 16 套。两边的 id 不会撞上。
- **名字**：插件的主题带一个文案键，照插件文案的约定取（ADR-0033）；钻石青的名字在 `packages/i18n` 里。

### 检查

检查的是补齐以后的完整取值，也就是实际画到页面上的那一套。

- 对比度：沿用 `tokens.test.ts` 的 25 组，亮暗分别查。
- 亮色是亮的、暗色是暗的：亮色下 `bg` 和 `text-inverse` 都比 `text` 亮，暗色下相反。theme.css 只在暗色下设 `color-scheme: dark`，把深色底塞进亮色的话，浏览器自己画的滚动条、输入框和底色对不上，二维码也会反色。
- 强调色和危险色要分得开：亮暗分别算 `accent` 和 `danger` 在 OKLab 里的距离，不小于 0.12。主要按钮和删除按钮不能看着一样。钻石青是 0.27 和 0.32，钴蓝是 0.36 和 0.27；洋红配默认的危险色都只有 0.10 左右，正是 DESIGN.md 附录说的"启用前把 danger 往橙红挪"。别的状态色之间不查：钻石青的强调色和成功色在亮色下只差 0.11，靠色相拉开，它是定稿时认可了的。

检查跑三次：
- `nextskin-plugin build`：作者构建时就知道哪套不通过，构建失败。
- 安装和升级插件时，核心用自己的默认取值再查一遍，不通过就拒绝。不信任插件的构建工具，同 ADR-0011 对入口的检查。错误码 `plugin_theme_invalid`，带主题名、模式、哪一组、实际的值。
- 核心每次加载插件时：核心升级后默认取值或规则变了，以前通过的主题可能不再通过。这时只有这套主题不可用，后台主题页列出它和原因；插件的其他功能照常，用户的选择按"回落"处理。

规则也是插件 API 的一部分：只放宽、不收紧。核心以后加颜色 token，要给它一条从已有 token 推导的默认值（像 `focus` 跟着 `accent`），保证旧主题加上新 token 以后照样通过。

### `packages/theme`

一个没有依赖的纯函数包：可改的 token 清单、钻石青的完整取值、推导、检查、生成 CSS。
- `packages/ui` 的测试用它检查 theme.css；
- `packages/plugin-host` 用它校验 manifest，构建命令和 host 的单文件包都打进去；
- `packages/domain` 用它建主题注册表、生成 CSS。

theme.css 仍是 token 的唯一来源（ADR-0012）：钻石青的取值由 `pnpm design:sync` 从 theme.css 生成到这个包里，测试守着两边一致，同 DESIGN.md §3 的表。对比度的组合从 `tokens.test.ts` 挪进这个包。

不放进 `packages/ui`：plugin-host 不该为了几个纯函数依赖组件库。不放进 `plugin-host`：`packages/ui` 的测试要用，组件库依赖插件的运行时也不对。

### SDK

`UiContributions` 加 `themes`：

```ts
ui: {
  themes: [
    {
      name: 'cobalt',
      label: 'themes.cobalt',
      colors: {
        light: { accent: '#2a52e5' },
        dark: { accent: '#86a2ff' },
      },
    },
  ],
}
```

- 新类型 `ThemeColor`：20 个可改 token 名的联合，和 theme.css 里的名字相同（不带 `--color-` 前缀）。它们从此是公开 API：改名或删除是大版本。测试守着 `ThemeColor` 加上锁住的三个，正好是 theme.css 的全部颜色：核心加了颜色 token，要么加进 `ThemeColor`（次版本），要么加进锁住的清单，不会漏掉。
- `light`、`dark` 都可以省略、都可以只写一部分。
- 不需要能力：主题只是数据，不运行代码，也读不到任何东西。安装前的确认和插件详情页列出"提供 N 套主题"。
- manifest 照样由构建命令提取，`ui.themes` 原样写进去（色值转小写）。核心只认 manifest（ADR-0033），拿主题、生成 CSS 都不用跑插件代码，也不用跨进程调用插件。
- type-tests 加上 token 名拼错、色值不是 `#` 开头的 `@ts-expect-error` 用例；作者文档加一页；附 changeset。趁候选期进 1.0。

### 主题注册表

可用的主题 = 钻石青 + 当前这一代已启用插件声明的、通过检查的主题，插件换代时重建（ADR-0009）。每套主题生成好的 CSS 跟着注册表缓存。

### 后台的主题页

`/admin/themes`，要 `settings.manage`（超级管理员），导航里排在"设置"后面。

- 每套可用的主题一张卡片：亮暗两份小样、名字、来源（内置，或者插件名并链到插件详情页）、"启用"开关、"设为默认"按钮。不通过检查的主题单独列在下面，写明原因，不能启用。
- 默认主题必须是启用的，不能关掉，要先把别的主题设为默认。
- 钻石青也能关掉（站长只想让用户看到自己站点的配色），只要它不是默认主题。它始终是回落的终点，见"回落"。
- 插件新带来的主题默认不启用：对比度通过不等于和站点的风格相配，由超级管理员看过再开。插件详情页写明"提供 N 套主题"，并链到主题页。

两个设置项，`section` 为 `null`，不出现在设置表单里，设置接口也改不了（ADR-0028），只由主题页的用例写：

| 键 | 默认值 | 用途 |
|---|---|---|
| `theme.default` | `'diamond'` | 站点默认主题：没登录的访客、没选过主题的用户用它 |
| `theme.enabled` | `['diamond']` | 启用的主题，用户只能从这里选 |

接口 `PATCH /api/admin/themes`，每次只交改动的部分：设默认，或者开、关某一套。用例在事务里按增量改写列表，两个超级管理员同时操作不会丢掉对方的改动。新启用或设为默认的主题必须当前可用，否则 `theme_not_found`；关掉默认主题是 `theme_default_disabled`。审计照常记 `setting.update`，带前后的值。

### 用户的选择

- 存进账号：`users` 加一列 `theme`（varchar(128)，可空），`null` 表示跟随站点默认。配色是个人口味，和设备无关，换了手机也该是同一套；亮暗按设备记，是因为手机和电脑常常想要不一样的设置（DESIGN.md §10），这一点主题没有。
- 没登录的访客看站点默认，不另存 Cookie。两处都存的话，要决定登录前后谁优先、登录时要不要同步，得不偿失。
- 接口 `PUT /api/user/theme`，`{ theme: string | null }`，由用例 `setTheme` 写：只能选启用的主题，否则 `theme_not_found`；封禁的用户不能改，同 `updateProfile`。
- 不经过 `updateProfile`，不发 `user.profileUpdated`，不进 SDK 的 `PrivateUser`，不记审计：插件用不上它，挑主题时连着点几下也不该展开成一串事件。
- 导入 BS 时，导入的用户 `theme` 为空，跟随站点默认。

### 用户中心的主题页

`/user/theme`，用户中心侧栏的一项，图标 `colors-swatch`，排在"个人资料"后面；启用的主题不到两套时不显示这一项。页头右上角的亮暗菜单在同样的条件下给登录用户加一项"主题…"链到这里。全站导航只有皮肤库和上传，不放它。

- 第一项是"跟随站点默认"，写明现在是哪一套；下面每套启用的主题一张卡片，亮暗两份小样，点一下就保存、整页换上。选中的卡片用加粗边框加勾选角标，同材质卡片（DESIGN.md §2.1）。
- 页面上方放亮暗模式的分段选择，和页头的菜单是同一个 Cookie：找"外观"的用户在一个地方就能改完。
- 用户选的主题被关掉或者没了时，页面写明"你选的主题已停用，现在跟随站点默认"。

小样是 `packages/ui` 的新组件 ThemeCard：一个缩小的页头、按钮、卡片和徽标，根元素带 `data-theme` 和 `data-mode`，配 story 和截图基线，DESIGN.md 组件清单补一行。

### 页面怎么上主题

主题在服务端就能定下来：登录用户的选择 → 站点默认 → 钻石青，见"回落"。不需要内联脚本：亮暗要等浏览器报告 `prefers-color-scheme`，主题不用。

- 根布局在 `<html>` 上写 `data-theme`，当前主题不是钻石青时在 `<head>` 里输出它的 `<style>`。钻石青就是 theme.css 本身，不输出。
- 生成的 CSS 写出两种模式下全部可改 token 的取值（已经补齐），限定在 `[data-theme='<id>']` 和 `[data-theme='<id>'][data-mode='dark']` 上，不依赖和 theme.css 之间的层叠顺序。限定在属性上，同一页里就能同时画几套主题：主题页给每张小样输出各自的 CSS（包括钻石青）。
- 一套主题的 CSS 约 1.5 KB。只输出当前主题，不把全部启用的主题塞进每个页面。
- CSP 不管样式（ADR-0053），`<style>` 不用带 nonce；色值都检查过，拼不进别的东西。
- 跟着主题变的：所有用 token 的地方，包括标志的像素图形、插件的声明式页面，以及以后运行时插件的样式（它们引用 `var(--color-*)`，ADR-0011）。
  二维码用 `text`、`text-inverse` 画，也跟着变；两者的对比度和明暗方向都在检查之内，照样扫得出来。
- 不跟着变的：站点图标（`pnpm design:sync` 从钻石青生成的静态文件；换图标走 ADR-0042 的上传）、邮件（`packages/email` 自带一份亮色取值，ADR-0020）。
- 安装向导里还没有设置，用钻石青；导入期间不查会话（ADR-0031），用站点默认。

### 回落

在读的时候算，不改写存着的值：

1. 用户选的主题仍然启用、可用 → 用它；
2. 否则，站点默认主题可用 → 用它；
3. 否则用钻石青，不管它启用没有。

插件停用、换代后某套主题没了、核心升级后检查不再通过，都只是暂时用不上：插件重新启用、主题恢复可用以后，用户和站点原来的选择照旧生效。

**卸载**插件时一并清掉它的引用：`theme.enabled` 里以 `<插件 id>/` 开头的项删掉，`theme.default` 指向它时改回 `diamond`，`users.theme` 指向它的改回 `null`。和卸载时删掉第三方账号绑定一样（ADR-0034），在卸载的事务里做。官方插件不能卸载，只有停用。

### 官方插件 `color-themes`

`plugins/color-themes`，名字"更多配色"，只有 `ui.themes`：
- 钴蓝 `color-themes/cobalt`：取附录的强调色，其余推导。
- 洋红 `color-themes/magenta`：附录的强调色，加上挪向橙红的 `danger`。挪了以后危险色可能和警告色靠得太近，必要时连 `warning` 一起调；取值在实现时定，过同一套检查后写进 DESIGN.md 附录。

它是这个扩展点的参考插件（ADR-0033 的做法）：只用公开 API 写成。核心因此只内置一套主题，不启用这个插件的站点没有主题可选，用户中心也就不出现主题页。

### 测试

- `packages/theme`：推导出的钻石青和 theme.css 一致；对比度和距离；生成的 CSS；各种不合法的输入。
- SDK：type-tests；`ThemeColor` 和 theme.css 的颜色对得上；api-extractor 报告更新。
- plugin-host：`ui.themes` 的校验，构建和安装都拒绝不通过的主题。
- 领域层（`*.db.test.ts`，四种数据库）：迁移、回落、`setTheme`、主题页的增量更新和并发、卸载清掉引用。
- e2e：用户选主题后 `<html>` 的 `data-theme` 和计算出的 `--color-accent` 变了；关掉这套主题后回落到站点默认；亮暗切换照旧（改名后的 `color-mode.spec.ts`）。
- 截图：组件的基线照旧只拍钻石青，不按主题翻倍；ThemeCard 的 story 拍亮暗两张。插件主题靠检查把关，不拍截图。

### 落地顺序

一个 `feat/color-themes` 分支，按顺序提交，全部做完再提 PR（ADR-0047：有迁移，改了 SDK 公开 API）：

1. 这份 ADR；
2. `data-mode` 改名；
3. `packages/theme`、`design:sync` 生成钻石青的取值、对比度检查挪过来；
4. 核心：注册表、设置项、`users.theme` 的迁移、用例和接口、根布局、后台和用户中心的主题页、ThemeCard；
5. SDK 的 `ui.themes`、构建和安装时的检查、type-tests、作者文档、changeset；
6. 官方插件 `color-themes`；DESIGN.md §2.3、§10、§11 和附录，PROGRESS.md。

## 后果

- 20 个颜色 token 的名字冻住了：改名或删除是插件 API 的大版本。DESIGN.md §2.3 和 §3 要写明哪些 token 是公开的。
- 检查规则只能放宽。核心以后加颜色 token，要给它一条推导规则。
- 插件主题好不好看没有人工把关，只有对比度、明暗方向和强调色、危险色的距离；这是新主题默认不启用的原因。
- 每个不是钻石青的页面多一段约 1.5 KB 的内联样式；主题页多几套。
- 访客只能看站点默认。用户换设备看到的是同一套主题，亮暗照旧按设备。
- 高对比主题还做不了。
- 站点图标、邮件始终是钻石青。只换了主题的站点，浏览器标签上还是青色的图标。
- `data-theme` 的意思变了。以后的自定义 CSS 或运行时插件按新的意思写。
- SDK 1.0 的公开面多一项；候选期里还能改，1.0.0 之后就冻住了。

## 考虑过的其他方案

- **插件提供 CSS 文件**：查不了对比度；能改动任何东西，DESIGN.md §11 的"插件没有办法改变观感"就不成立了；还要防 CSS 里拼进别的东西。要改观感的插件以后走运行时组件或自定义 CSS。
- **开放全部 token，包括圆角、字体、动效**：冻住的名字更多；高对比要的边框粗细、静止阴影、链接下划线现在根本不是 token，开放了也做不成。
- **主题必须写全部颜色**：作者要抄一遍钻石青的灰色，核心以后调灰色时插件主题不跟着变；钴蓝、洋红本来就只改一组颜色。
- **不推导 `focus` 和 `accent-subtle`，没写就取钻石青**：只改强调色的主题会留着青色的焦点框和淡底，作者几乎一定会忘。
- **用户的选择按设备记在 Cookie 里**（同亮暗）：不用迁移，访客也能选；但配色和设备无关，换设备要重选。**账号和 Cookie 都存**：登录前后谁优先、登录时怎么同步都要另定。
- **"主题"放进全站导航**：全站导航只有皮肤库和上传两项，是给所有访客的；主题只有登录用户能选。
- **只在页头的菜单里选，不要页面**：菜单画不下小样，主题一多也排不开。菜单里保留一个入口。
- **新主题默认启用**（存"关掉的主题"而不是"启用的主题"）：为了别的功能启用一个插件，会顺手改变所有用户能选的东西；对比度通过也不保证和站点的风格相配。
- **经过 `updateProfile`、发 `user.profileUpdated`**：和语言一致，但插件用不上主题，加进 `PrivateUser` 是又一处 SDK 变更，连着点几下就是一串事件。
- **亮暗保留 `data-theme`，主题另起名（`data-palette`）**：代码里的 theme 和文档里的"主题"意思不一样，以后每个读代码的人都要分辨一次；运行时组件开放以后再改就是大版本。
- **主题也用内联脚本在浏览器里设**：服务端已经知道主题，多一段脚本没有好处。
- **一个样式表装下全部启用的主题，长期缓存**：每页都下载用不上的主题，开关主题时还要换地址。主题不多，内联当前这一套更简单；真有很多套再改成按主题分开、带 hash 的样式表。
- **钴蓝、洋红内置在核心**：不启用插件也有主题可选，但扩展点就没有参考插件验收，第一个用它的会是第三方作者。
- **检查规则放在 `packages/ui` 或 `plugin-host`**：见"`packages/theme`"一节，两个方向的依赖都不对。
- **查全部状态色两两之间的距离**：钻石青自己的强调色和成功色就只差 0.11，定稿时是靠色相拉开的。只查真会误操作的强调色和危险色。
