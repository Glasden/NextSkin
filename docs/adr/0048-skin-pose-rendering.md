# ADR-0048 皮肤改成 3D 等轴出图，悬浮时抬手

- 状态：已采纳
- 日期：2026-10-21

## 背景

ADR-0017 定下的 SkinFigure 是平面的 2D 正背面：正面横向缩到 0 再展开背面，分四格转身。站长看过之后嫌它简陋，想要 BS 皮肤库那样的效果：

- 背面和正面并排；
- 人物斜着站、略微俯视，外层（帽子、外套）立体地鼓出来，各个面有明暗。

另外想要鼠标移上去时人物抬起手臂。

这个改动有三点要先说清楚：

- **负载。** 默认部署在 1 核 2G、带宽很小的服务器上（ADR-0002），皮肤库一屏二十多张卡片。
- **要推翻已有的规则。** DESIGN.md §2.2 的招牌元素"转身"要换掉；§5 规定"只做整数倍缩放、不对材质做非 90° 的旋转"，等轴投影下一个材质像素会变成宽窄不一的平行四边形，这一条也要放宽。
- **ADR-0017 的其余结论要保留。** 服务端出图、组件服务端渲染、不要求材质的 CORS、出图地址里带渲染器版本，这些都不变。

## 决定

### 出图

- `packages/skin` 新增 `renderPose`，和 `renderFigure` 一样是只读写 RGBA 类型化数组的纯函数，浏览器的上传页也能用。
- 画法是软件光栅化：
  - 每个部位的内层、外层都是盒子，外层按游戏的膨胀量放大（头 0.5，其余 0.25）；
  - 相机绕竖直轴转 30°、俯视 18°，正交投影；
  - 逐像素按面的仿射逆变换取最近的材质像素，深度缓冲判断遮挡；
  - 外层半透明的像素从远到近叠上去，合成沿用 S4 的 `over`。
- 明暗按相机空间的法线算：顶面 1，朝着相机的正面 0.9，侧面约 0.72，底面 0.4。光源固定在相机空间，所以背面那个人和正面那个人一样亮。
- 三角函数值写成字面量，不在运行时调用 `Math.cos`：各个 JS 引擎的 `Math.cos` 不保证逐位相同，而出图要逐位稳定（黄金图、immutable 缓存）。
- 视角有两种：
  - `both`：背面在左、正面在右，用在材质卡片、衣柜、角色卡、上传页；
  - `front`：只有正面，用在领奖台、插图（登录、安装、维护页、启动器授权页）和 ×3 的迷你缩略图。迷你缩略图在手机上只有约 90px 宽，放不下两个人。
- 披风没有 3D 出图，照旧用 ADR-0017 的 2D 拼图，改为正面和背面并排显示，不再转身。

### 抬手

- 抬手拼图有 5 帧，从左到右排开：第 0 帧站着，和静止图逐像素相同；后面四格把左臂绕肩膀侧举到 150°。
- 抬的是左臂：正面看它在画面右侧，背面看它在画面左侧，`both` 视角里两只抬起的手都在外侧，不会挡住另一个人。
- 版式由 `poseLayout(view)` 给出，单位是标准像素，组件和出图共用：
  - 一帧的宽高包括手臂扫过的地方；
  - 站着时人物占的方框按整数对齐，1x、2x 两档正好差一倍；
  - 还给出脚下投影的四个顶点。
- 组件按站着的方框排版，抬起的手臂伸到方框外面。

### 分辨率

- 等轴投影没法"按材质分辨率出图、浏览器整数倍放大"。改成按显示需要出图：出图密度 p 是一个标准像素占多少个输出像素，等于显示倍数乘设备像素比（1x、2x 两档）。浏览器不缩放，像素照样锐利。
- p 取 1 到 16（×8 的插图在 2x 屏上是 16），和材质倍数 s 无关：高清皮肤在 p 小于 s 时按中心取样。

### 地址、缓存和编码

- 地址是 `/render/v{版本}/{both|both-raise|front|front-raise}/{steve|alex}/{p}/{hash}.png`。缓存键、访问控制、immutable 响应头、并发合并、worker 池排队都沿用 ADR-0017。
- 渲染器版本升到 2：黄金图的用例变了，旧版本的缓存整批删掉，2D 拼图和头像也换了地址。
- 皮肤上传时预热 `both` 的 p = 3、4、6、8 和 `both-raise` 的 p = 4、8；其余（领奖台、插图、迷你卡片的 2x）在第一次被请求时生成。
- 所有出图改用调色板 PNG：不同的 RGBA 颜色不超过 256 种时写 8 位调色板，否则退回原来的编码。普通皮肤加上明暗以后一般在 50 到 200 种颜色之间，比 RGBA 编码小 35% 到 50%。材质存储的编码不变。

### 组件

- SkinFigure 仍然可以在服务端渲染：地址、版式都在服务端算好，首屏 HTML 里就有静止图。
- 抬手交给一个很小的客户端组件：
  - 祖先元素带 `group/raise`（材质卡片、角色卡、领奖台）时，鼠标第一次移上去或键盘聚焦它，才下载抬手拼图；
  - 下载好就把静止图换成拼图（静止图只是变透明，替代文字还在），之后悬浮时用 CSS 的 `steps(4)` 把拼图挪四帧，移开时倒着播回去；
  - 触屏不下载；开启"减少动态效果"时不下载、不播放。
- `src` 改成 `(n, view, raise) => 地址`：皮肤的 n 是出图密度 p，披风的 n 照旧是分辨率 k。
- FigurePlaceholder 改成同一套几何的人形剪影：经典模型站着时内层朝向相机的面，按明暗分三档浅色，尺寸和 SkinFigure 相同。

### 负载

在 ARM 服务器上实测，未做优化，用 `packages/skin/test/fixtures` 里的 7 张皮肤：

| | ADR-0017 的 2D 拼图 | 静止图 | 抬手拼图（5 帧） |
|---|---|---|---|
| 首次出图的 CPU（材质卡片 2x，p = 8） | 不到 1 ms | 渲染 4–6 ms，编码 10–28 ms | 渲染 19–23 ms，编码 38–92 ms |
| 材质卡片 2x 屏的体积，普通皮肤 | 0.2–1.9 KB | 2–8 KB（颜色超过 256 种的一张 15 KB） | 8–19 KB（同一张 48 KB） |
| 同上，512×256 高清皮肤（颜色多，不用调色板） | 52 KB | 64 KB | 123 KB |

- **CPU 只花一次。** 出图按 immutable 缓存，上传时预热；只有导入的旧材质和升了渲染器版本以后才在第一次请求时生成。
- **列表页多的是流量。** 一页 20 张卡片、2x 屏，普通皮肤从约 20 KB 涨到 40–160 KB。抬手拼图只在碰过的卡片上下载。
- **浏览器几乎没有开销。** 动画是 CSS 的阶跃位移，没有 WebGL，也不在浏览器里读像素。

## 后果

- **DESIGN.md 跟着改：**
  - §2.2 的招牌元素"转身"换成"抬手"；
  - §5 的整数倍规则对 3D 出图改成"按显示密度出图、浏览器不缩放"；
  - §6 的 SkinFigure、FigurePlaceholder 两行重写。
- **父元素不要裁掉两侧。** 材质卡片的展台宽度要能放下抬起的手（×4 时一帧宽 200px）；窄到放不下时，抬起的手会被卡片裁掉一点，不影响排版。
- **Storybook 的出图只有 1x。** 截图测试跑在 1x 屏上；fixtures 里 2x 的地址退回 1x，没人悬浮的人物没有抬手拼图，退回同一视角的另一张。
- **出图的种类变多了。** 一张皮肤最多有 4 种 × 2 个模型 × 16 档 p 的缓存条目。实际用到的只有十来种，p 有上限，生成任务照旧进 worker 池排队。

## 考虑过的其他方案

- **列表里每张卡片一个 WebGL（skinview3d）。**
  - 浏览器同时能开的 WebGL 上下文大约只有 16 个；
  - 列表页要多加载 three.js；
  - 材质放在 S3 或 CDN 上时要配 CORS（ADR-0017）；
  - DESIGN.md 本来就写着"列表里 3D 太重"。
- **抬手拼图和静止图合成一张，首屏就下载。** 组件不需要 JS 就能抬手，但每张卡片首屏要多下载 2–3 倍的字节，而大部分卡片不会被碰到。
- **只用 CSS、不写 JS，悬浮时才把拼图设成背景图。** 第一次悬浮时拼图还没下载好，要么人物闪空，要么透过拼图的透明处露出静止图里垂着的手臂。CSS 判断不了图片下载好没有，只能加一个很小的客户端组件。
- **只把手臂单独出图，用 CSS 旋转。** 违反"不对材质做非 90° 的旋转"，转出来的像素是斜的；手臂和身体的前后遮挡也不对。
- **抬手的帧数做多、做平滑。** 拼图按帧数变大；四格的阶跃动作也正是 DESIGN.md 的"像素基因"。
- **在浏览器里用 canvas 出 3D 图。** 理由和 ADR-0017 放弃浏览器拼图的理由一样：要等水合、要读材质像素（CORS）、要把渲染包发给每个页面。
