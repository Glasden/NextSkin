# ADR-0002 部署基线：单进程、单数据库起步，Redis/S3/容器为可选档位

- 状态：已采纳（队列可以换成 Redis 驱动一条已被 ADR-0021 取代；启动器的进程模型、命令和发行目录由 ADR-0039 补充，`plugin` 命令推迟；"可观测性"一条已被 ADR-0062 取代）
- 日期：2026-10-16

## 背景

BS 的主力用户是在 1 核 2G 云服务器上、用宝塔或 1Panel 部署的 Minecraft 服主：下载发行包、解压、在网页向导里完成安装。另一端是 LittleSkin 这类大站，需要多实例部署和对象存储。研讨报告默认按大站设计（K8s、强制 Redis、每个插件一个容器），不适合前者。

## 决定

- **默认部署**：一个 Node 进程加一个数据库，SQLite 即可。不依赖 Redis、对象存储、Docker。
- **唯一入口是 `nextskin` 启动器**，它同时是进程监管者和命令行工具：
  - `start`：拉起核心进程和 plugin host（ADR-0009），崩溃自动重启；
  - `migrate`、`import`（ADR-0006）、`doctor`（环境自检）、`plugin`（安装与管理）。
- 宝塔的 Node 项目管理器指向 `nextskin start` 即可运行，不需要在服务器上安装依赖或编译。
- 缓存、会话、队列、限流、材质存储都先定义接口：
  - 默认实现用数据库、内存和本地磁盘；
  - Redis 和 S3 兼容存储是可选驱动，多实例部署时启用；
  - 插件隔离到容器是可选档位。
- 配置分两层：数据库连接和密钥放在 `.env`；其余一切存在数据库里，在后台修改。不使用 `NEXT_PUBLIC_*`，因此同一份构建产物可以分发给所有人。
- 发行物：一个通用 ZIP 包（前提是 ADR-0008 成立），外加 linux/amd64、linux/arm64 两种架构的 Docker 镜像。
- 可观测性：Pino 结构化日志，OTel 导出可选。核心内置一个用内存环形缓冲做的诊断页，并能一键导出脱敏诊断包。对服主来说，这比接入外部监控平台更有用。

## 后果

- 每个基础设施能力都要有"无外部依赖"的默认实现，并且 CI 要覆盖这些默认实现。
- 多实例部署不是默认能力，需要显式切换到 Redis 和 S3 驱动，文档要写清楚。

## 考虑过的其他方案

- **把 Redis 设为必需**：会让大量小站多部署一个服务，换来的好处只在多实例时才有意义。
- **把 Vercel/Serverless 作为一等目标**：和运行时安装插件的模型冲突，也不是目标用户的部署方式。
