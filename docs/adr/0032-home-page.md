# ADR-0032 首页：领奖台按最近 7 天新加进衣柜的次数排前三名；站点描述和页脚交给新的设置项；新标志，favicon 由 token 生成

- 状态：已采纳（自定义站点图标和标志、页脚的图片由 ADR-0042 补充；favicon 按 Next 的文件约定放置、不读站点设置的部分已被 ADR-0042 取代；`meta_extras`、`custom_js` 留给的设置项由 ADR-0063 落地为页头代码）
- 日期：2026-10-18

## 背景

首页还是占位：`app/page.tsx` 只有一个写着 NextSkin 的标题。站点也没有 favicon，浏览器请求 `/favicon.ico` 得到 404。

已经定了的：
- DESIGN.md §2.2：首页主视觉是领奖台，本周收藏最多的三个皮肤站在台阶上。台阶高 104 / 80 / 64px，第一名用 `accent`；皮肤按 ×5 显示，头顶有名牌。
- 视觉定稿的样稿（2026-10-17）给出了首页的结构：左边是介绍、主要操作和站点统计，右边是领奖台；下面是材质网格、"三步用上外置登录"和页脚。
- ADR-0025 把领奖台留给首页；ADR-0028 把 BS 个性化页里的首页图、版权文字、站点描述和 SEO（`meta_*`）留给首页。

BS 的首页：
- 大标题是站点名，下面是站点描述（`site_description`，按语言存多份），再下面一个按钮：没登录时是"注册"，登录后是"用户中心"；
- 整页铺一张背景图（`home_pic_url`），可以固定背景（`fixed_bg`）、导航栏透明（`transparent_navbar`）；
- 背景图下面是三条写死的"优势"（多角色、分享、永久免费）和一段介绍，可以用 `hide_intro` 关掉；
- 页脚是 `copyright_text`：原始 HTML，`{site_name}`、`{site_url}`、`{year}` 会被替换；旁边是不许删的 "Powered by Blessing Skin Server"，`copyright_prefer` 只能在七种说法里选一种；
- 页面头部有 `favicon_url`、`meta_keywords`、`meta_description` 和 `meta_extras`（原始 HTML，原样插进 `<head>`）。

现行标志是头部六个面在皮肤材质里的排法：上一行是顶和底，下一行是右、前、左、后，宽高 2:1，上一行空着两格。放进 16px 的正方形图标只剩一道细条，小尺寸下也容易看成散开的色块。

还没定的：领奖台的"本周"怎么算、不满三个时怎么办；首页放哪些内容；BS 的这些设置哪些保留；页脚放在哪些页面；标志改成什么样、favicon 怎么生成。

## 决定

### 范围

这次做：
- 首页 `/`：主视觉（介绍、主要操作、站点统计）和领奖台、最新上传、三步用上外置登录；
- 全站页脚 SiteFooter；
- 新设置项 `site.description`、`site.keywords`、`site.footer`；
- 根布局的 SEO 元数据；
- 新标志和 favicon；
- 导入器的 options 对照补上这几项。

不做：
- 首页背景图：主视觉是领奖台（DESIGN.md §2.2），见"考虑过的其他方案"。`fixed_bg`、`transparent_navbar`、`hide_intro` 随之不做。
- 自定义站点图标（BS 的 `favicon_url`）：以后随"站点外观"（上传站点图片）做。BS 的值一般是它公开目录下的相对路径，迁移以后本来就失效。
- `meta_extras`：原始 HTML，和自定义 JavaScript 一样，留给受管控的"统计/广告脚本"设置项（ADR-0010、ADR-0028）。
- 全站公告条（DESIGN.md 的 Notice）：ADR-0028 的决定不变，公告仍在仪表盘上。
- Open Graph 预览图、结构化数据、PWA manifest。
- 首页的插件插槽：随插件运行时做。

### 领奖台

**排什么**：公开的皮肤（`steve`、`alex`），不含披风。领奖台上站的是人。

**怎么算**：最近 7 天新加进衣柜的次数，也就是 `closet_items.created_at` 落在区间里的行数。
- 区间按站点时区算，从 6 天前的 0 点到现在。标题旁边写日期，例如"10.12 – 10.18"。
- 不算上传者自己衣柜里的那一件。上传时材质会自动放进上传者的衣柜（ADR-0025），算上的话每个新材质白得一次。
- 只数还在衣柜里的。移出时行就删了，这一次也不再算，和收藏数（`textures.likes`）的口径一致。
- 次数相同时按总收藏数倒序，再按 id 倒序。
- BS 导入的衣柜，`created_at` 是导入时刻（schema.md）。导入后的头 7 天，领奖台实际按导入时的整个衣柜排，相当于总收藏榜，之后自然过渡到最近 7 天。

**不满三个**：最近 7 天一次都没被收藏过的皮肤不上榜。空着的台阶上放 FigurePlaceholder，不拿总收藏数补位：补上来的不是"最近 7 天"，台阶上的"♥ +N"就说不通了。一个都没有时台阶照样摆着，标题下写"最近 7 天还没有人收藏皮肤"，给一个去皮肤库的链接（DESIGN.md §7 的空状态）。

**显示**：台阶从左到右是第二、第一、第三名。名牌写材质名，台阶上写名次和"♥ +N"（这 7 天的次数）。点角色进材质详情；鼠标移上去或键盘聚焦时转身（DESIGN.md §2.2）。

**查询**：`closet_items` 加 `created_at` 上的索引。按时间区间取最近 7 天的行，按 `texture_id` 分组计数，再关联 `textures` 过滤公开、类型和上传者。

**不防刷**：小号互相收藏能冲上去。BS 没有排行榜，NextSkin 也只有这一个；榜上的材质都是公开的，可以举报。真成了问题再加计入条件，例如注册满 N 天的账号才算。

### 首页内容

从上到下：

1. **页头**：SiteHeader，与皮肤库相同。

2. **主视觉**：宽屏左右两栏，窄屏领奖台排在文字下面。
   - 一行小字："Minecraft 皮肤站 · 支持外置登录"，像素字体 ×1。
   - 主标题："给角色换身衣服"，像素字体 ×4，窄屏 ×3。界面文案，不是站点名：页头的标志紧挨着就写着站点名，再写一遍大字是重复。站点名仍是页面的 `<title>`。
   - 站点描述：`site.description`。空的时候用界面文案里的默认句子（"上传皮肤和披风，配合外置登录，在支持的服务器里穿上它们。"）。站长要的自定义落在这里，对应 BS 的站点描述。
   - 两个按钮，按登录状态换，同 BS：

     | 状态 | 主要按钮 | 次要按钮 |
     |---|---|---|
     | 没登录、开放注册 | 注册 | 浏览皮肤库 |
     | 没登录、关闭注册 | 登录 | 浏览皮肤库 |
     | 已登录 | 上传材质 | 用户中心 |

   - 站点统计：公开材质数、用户数、角色数，像素字体 ×2。不放样稿里的"今天上传"：小站多数时候是 0。

3. **最新上传**：最新的 10 个公开皮肤，用 TextureCard 网格（窄屏 2 列，宽屏 5 列），标题旁边是"去皮肤库"的链接。查询与皮肤库的"最新"相同。还没有材质时用 EmptyState："还没有人上传材质"，操作是"上传第一个材质"。

4. **三步用上外置登录**：
   1. 注册并添加角色；
   2. 在启动器里添加外置登录：显示 API 地址，带复制按钮，按钮也能拖进启动器，与仪表盘相同（ADR-0030）；地址的算法也与仪表盘相同；
   3. 进服务器，换上皮肤。

   仪表盘上的那一节是给已经注册的人的操作步骤（含两步验证的说明），首页这一节是给还没注册的人看的概览。

5. **页脚**：见下一节。

**缓存**：站点统计和领奖台的结果在进程里缓存 60 秒。首页是访问最多的页面，用户数和角色数是整表计数，在导入的大站上每次要几十毫秒。部署基线是单进程（ADR-0002）；多实例时各自缓存，数字差几十秒没有关系。最新上传不缓存：刚上传的材质应该马上出现，查询也只是倒序扫索引取 10 行。

首页只读，不需要新的 REST 接口：和其他页面一样，服务端组件直接调用领域层的查询。

### 页脚

SiteFooter 用在首页、皮肤库和用户中心。后台、登录注册、安装向导、维护页不用：后台有自己的侧栏，登录注册是带插图的两栏全屏页，安装向导和维护页是独立的全屏页。

内容：
- 左边：标志（小号）和站点描述（同首页，空的时候用默认句子）；
- 中间两列链接，只放存在的页面：站点（皮肤库、上传材质）、账号（用户中心、衣柜、角色）。没登录时也显示，点了先去登录；
- 底部一行：左边是 `site.footer`，空的时候显示"© {年份} {站点名}"；右边是"由 NextSkin 驱动"。

`site.footer`：
- 按 Markdown 渲染，用现有的 Markdown 组件：原始 HTML 去掉，链接只放行 http、https、mailto 和站内路径（ADR-0028）。主要用途是 ICP 备案号：中国大陆的站点要在页脚放备案号并链接到工信部的网站，写成 `[京ICP备12345678号](https://beian.miit.gov.cn/)` 即可；
- `{year}` 换成站点时区的当前年份，免得每年改一次。不提供 BS 的 `{site_name}`、`{site_url}`：直接写就行，它们不会自己变；
- 填了以后替换掉默认的"© {年份} {站点名}"，不是接在后面。

"由 NextSkin 驱动"固定显示，不提供开关，也不带版本号：版本号对访客没有用，还会告诉别人这个站没升级。

### 新设置项

都在 `site` 分区：

| 键 | 类型 | 默认值 | 用途 |
|---|---|---|---|
| `site.description` | 字符串，最长 200 个字符 | `''` | 首页主标题下的一句话、页脚标志下的一句话、页面的 meta description |
| `site.keywords` | 字符串数组 | `[]` | 页面的 meta keywords |
| `site.footer` | Markdown，最长 2000 个字符 | `''` | 页脚底部一行 |

`site.description` 和 `site.footer` 只有一份，不按语言区分，同 `site.announcement`（ADR-0028）。

### SEO

根布局的 metadata 加上：
- `description`：`site.description`，空的时候用默认句子；
- `keywords`：`site.keywords`，空数组时不输出；
- `openGraph`：只有 `siteName`、`title`、`description` 和 `type: website`，不带图片。QQ、Discord 这类聊天软件贴出站点链接时会显示站点名和描述。

### 标志

提议阶段比较了三个候选：折起来的头、等轴方块头、十字展开图，选定折起来的头（另外两个见"考虑过的其他方案"）。

- 图形：把现行的展开图折回成一个方块头。画在 8×8 的网格上：前脸 6×6 用 `accent`，顶面和右侧面各两格深，分别用 `text-muted` 和 `border-strong`；前脸上两只眼睛，各 1×2 格，用 `accent-fg`。
- 尺寸都是整数倍：页头每格 4px（32px），后台侧栏和页脚每格 3px（24px），favicon 的 16px 每格 2 像素。
- Logo 组件的接口不变（站点名、`size`、`render`）。图形的网格只定义一次，放在 `packages/ui`，Logo 组件和 favicon 的生成脚本共用。
- DESIGN.md §2.2 的"标志"一行随之改写，Logo 的 story 和截图基线更新。

### favicon

- 用 Next 的文件约定放在 `apps/web/app/` 下，所有页面（包括安装向导和维护页）都有：
  - `icon.svg`：内嵌 `prefers-color-scheme` 的暗色取值，Chrome、Firefox、Edge 的标签栏跟着亮暗切换；
  - `favicon.ico`：内含 16、32、48 三种尺寸，PNG 编码，用亮色取值。给不认 SVG 图标的浏览器（Safari）用；
  - `apple-icon.png`：180×180，白底（iOS 会把透明的部分填成黑色），标志每格 16px 居中。
- 三个文件都是静态的，不读站点设置，浏览器和 CDN 可以长期缓存。
- 颜色由 `pnpm design:sync` 从 `theme.css` 读出来生成这三个文件，同 DESIGN.md 的 token 表；测试检查文件和 token 一致，改了 token 忘了同步会失败。
- 维护模式的 `proxy.ts` 放行这几个文件，与现在放行 `/favicon.ico` 相同。

### 导入

options 对照表补上：

| BS | NextSkin | 规则 |
|---|---|---|
| `site_description_{语言}`、`site_description` | `site.description` | 取与 `site.locale` 对应的那份，没有就取不带后缀的，同公告。等于 BS 的默认值时不导入；超过 200 个字符时截断，在报告里注明 |
| `meta_keywords` | `site.keywords` | 按半角和全角逗号拆开，每项 trim，去掉空项 |

不导入，不是默认值时在对账报告里列出：
- `meta_description`：NextSkin 的 meta description 就是站点描述。与 `site_description` 不同时，报告里列出原文；
- `copyright_text`：BS 的版权文字是原始 HTML，按 Markdown 渲染时 HTML 会被去掉，备案号的链接也就没了。报告里列出原文，请站长改写成 Markdown 填进 `site.footer`；
- `home_pic_url`、`favicon_url`、`meta_extras`、`copyright_prefer`、`fixed_bg`、`transparent_navbar`、`hide_intro`、`navbar_color`、`sidebar_color`、`custom_css`、`custom_js`。

## 后果

- 首页每次请求查最新的 10 个材质，加上每 60 秒一次的统计和领奖台。皮肤库、用户中心多了页脚，它要读站点描述和 `site.footer`，与页头读站点名一样走设置的查询。
- 主标题是界面文案，站长只能改站点描述；以后做"覆盖翻译"时一并可改。
- favicon 只有默认主题的颜色。做主题切换时，改成按主题生成，或者让 `icon.svg` 引用主题的颜色。
- 导入的站点头 7 天的领奖台是总收藏榜，见"领奖台"。
- 迁移过来的站点要重新填页脚的备案号（对账报告里会提醒）。

## 考虑过的其他方案

- **按自然周（周一到周日）排**：每周一领奖台清空，头几天空着或只有零星几个。最近 7 天滚动，什么时候打开都有内容。
- **按总收藏数排**：几乎不变，老材质一直占着；皮肤库已经有"最热"排序。
- **不满三个时用总收藏数补位**：见"领奖台"。
- **主标题用站点名**（BS 的做法）：和页头的标志重复，见"首页内容"。
- **保留首页背景图**：和领奖台抢主视觉；材质要站在 `stage` 上才看得清（DESIGN.md §10），铺在照片上不行。
- **页脚用纯文本**：备案号要能点。
- **页脚允许原始 HTML**（BS 的做法）：ADR-0028 已经不渲染原始 HTML。
- **favicon 动态生成**（`icon.tsx` 加 `ImageResponse`）：要带上 satori 和 resvg 的 WASM，只为几张固定的小图不值得；静态文件还可以长期缓存。
- **把 `meta_description` 单独做成设置项**：站点描述和 meta description 在绝大多数站点上是同一句话，分开只是多一个要填的框。
- **统计和领奖台不缓存**：皮肤库每次请求都数总数，但那是一个带条件、走索引的计数；首页的用户数和角色数是整表计数，导入的大站上 PostgreSQL 和 MySQL 都要扫表。
- **等轴方块头、十字展开图做标志**：前者是 16×16 的网格，24px 不是整数倍，灰色面积比强调色大，等轴方块也是 Minecraft 周边最常见的图形；后者小尺寸下像加号或医疗十字，也不再是皮肤材质里头部的真实排法。
