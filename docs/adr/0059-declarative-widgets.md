# ADR-0059 声明式挂件：插件在用户中心首页和后台概览放统计或 Markdown 的挂件，由核心在服务端渲染；插槽名和以后的运行时组件共用

- 状态：已采纳（插槽的登记表和文档站的插槽一览由 ADR-0060 补充）
- 日期：2026-10-23
- 补充 ADR-0011：声明式一档多了"在插槽里放挂件"；它定下的插槽列表（`SlotName`）从这里开始
- 补充 ADR-0033：做它"推迟"表里"运行时组件和插槽"的插槽部分，只做声明式的两个插槽，趁 SDK 候选期进 1.0

## 背景

ADR-0011 把插件 UI 分成三档，插槽只出现在运行时组件那一档。SDK 草案里另有声明式的挂件：`widgets: { slot, title?, view }`，插槽有五个（`user.dashboard`、`admin.dashboard`、`user.profile.sections`、`skinlib.detail.sidebar`、`player.card.footer`）。ADR-0033 把运行时组件和插槽一起推迟，草案里的 `widgets` 和 `SlotName` 随之删掉。推迟的理由（把 React 的大版本绑进插件 API，要先做 import map、shim 和 CSP）说的是运行时组件，声明式的挂件不受这些限制。

现状：
- 插件在界面上能做的只有四件：自己的页面（表格、表单、统计、Markdown）、导航项、注册表单的字段、配色主题。插件想对用户说一句话（"你还没绑定"、"这是你的分享链接"），用户得自己点进导航。BS 的插件做这件事靠往页面里注入 HTML，ADR-0011 不允许。
- 页面的数据源由服务端组件调用插件的 GET 路由（`apps/web/lib/plugins.ts` 的 `getPluginRoute`），检查和浏览器经过网关一样，不走 HTTP。路由限时 30 秒。统计和 Markdown 视图的渲染已经有了（`plugin-page-view.tsx`）。
- 后台概览的代码里留着"插件的 admin.dashboard 插槽以后放在这里"。
- SDK `1.0.0-rc.6` 已合进 main，还没发布正式版。

要定的：开哪些插槽、插件怎么声明、挂件里能放什么、谁看得到、数据怎么取、失败和"不显示"怎么表达、放在页面的哪里、和以后的运行时组件是什么关系。

## 决定

### 范围

这次做：
- `ui.widgets`：插件往插槽里放挂件，挂件的内容是统计或 Markdown 视图；
- 两个插槽：用户中心首页 `user.dashboard`、后台概览 `admin.dashboard`；
- 核心渲染挂件；后台"这个插件会做什么"和命令行列出挂件；
- 参考插件：分享注册链接在用户中心首页放一个，邀请码在后台概览放一个。

不做：
- **挂在具体对象上的插槽**（草案里的材质详情、角色卡片、个人资料）：要定传给数据源的上下文（tid、pid）和私有材质的可见性；放在列表里的角色卡片，每张卡就是一次插件调用。没有参考插件需要，照旧推迟。
- **首页（公开页面）的插槽**：首页对匿名访客也渲染，每个请求都要调插件。没有参考插件需要。
- **挂件里放表格、表单、操作按钮**：首页上放不下分页和搜索。要操作的，链到插件自己的页面。
- **站长调整挂件的顺序、隐藏某个挂件**：等插件多了再看需不需要。
- **运行时组件**（`ui.script`）：照旧推迟（ADR-0033），和它的关系见"插槽和运行时组件"。

### 声明

```ts
ui: {
  pages: {
    links: { area: 'user', title: 'page.links', view: { kind: 'table', source: '/codes', columns: [/* … */] } },
  },
  widgets: [
    {
      name: 'share',
      slot: 'user.dashboard',
      title: 'widget.title',
      link: { page: 'links', label: 'widget.manage' },
      view: { kind: 'markdown', source: '/widget' },
    },
  ],
}
```

| 字段 | 说明 |
|---|---|
| `name` | `[a-z][a-z0-9-]{0,63}`（同页面名），同一插件内不重复。核心用它区分挂件、在报错里指明是哪一个 |
| `slot` | `SlotName`，第一版是 `'user.dashboard' \| 'admin.dashboard'` |
| `title` | 标题的文案键，必填 |
| `permission` | 可选，本插件声明过的权限名，同页面 |
| `link` | 可选，`{ page, label }`：标题右边的链接，指向本插件的一个页面，页面的 area 要和插槽一致（`user.dashboard` 对 `user`） |
| `view` | `WidgetView`：只能是 `stats` 或 `markdown`，形状和页面的视图相同 |

- 一个插件在一个插槽里最多放 2 个挂件。首页是大家共用的地方，一个插件不该占满它。以后可以放宽，不收紧。
- 挂件总有标题：首页上的每一块都有标题，读屏器按标题跳转；没有标题的块，看起来就像核心自己的内容。
- 链接只能指向本插件的页面，不能写任意地址：路径的格式由核心拼，以后改页面地址时插件不用跟着改。看的人没有权限看那个页面时，链接不显示。
- 不需要能力，不改变安装前的确认：挂件只是声明，数据来自插件已经声明的路由。"这个插件会做什么"列出它的挂件（放在哪、叫什么）。

检查：SDK 的类型先拒绝拼错的插槽、表格或表单视图、没声明的权限；构建命令和 plugin host 再查一遍名字、重复、个数、链接的页面和区域、路径和权限；安装时 manifest 的 schema 也认得这一项。

### 谁看得到

- `user.dashboard`：登录了、没被封禁的用户。声明了 `permission` 的，只有拥有这项插件权限的人看得到（第一版就是管理员和超级管理员，同页面）。
- `admin.dashboard`：管理员和超级管理员，同后台的插件页面。
- 这只决定显示不显示。数据源路由照常由网关检查 `auth` 和 `permission`，作者要两边分别声明，同页面。

### 数据

- 和页面的数据源一样：服务端渲染时调用插件的 GET 路由，经过同样的检查（身份、权限、限流），不走 HTTP。统计返回 `StatsSourceResponse`，Markdown 返回 `text/markdown`。
- **限时 3 秒**（页面的数据源是 30 秒），超时按失败处理。首页是登录以后的第一页，挂件慢了整页跟着慢。要访问外部服务的插件，先用任务或定时任务把结果存进插件表或 KV，挂件只读本地。
- **和页面的其余数据一起取完再渲染**，不分块流式。各个挂件同时取。分块流式的话，先显示骨架、再换成内容，挂件下面的内容会跳；返回 204 的挂件还会整个塌掉。插件的路由在本机，正常几毫秒就返回，3 秒只在插件出了问题时才会等满。
- **不传上下文**：两个首页插槽只有"当前用户"，路由的 `scope.actor` 里已经有了。以后挂在对象上的插槽再定怎么传。
- **不缓存**：每次打开页面调用一次。按用户限流的路由，刷新得太快会失败，作者给挂件的路由不要设太紧的限流。

### 显示

- **返回 204**：整个挂件不显示，标题也不显示。插件用它按条件出现，比如只提醒还没完成某件事的用户。
- **失败**（超时、出错、其他状态码、形状不对）：标题照常显示，正文换成一行灰字"没能加载"。不用插件页面上那种 danger 的 Alert：首页上的人多半处理不了插件的故障，红色太抢眼；不显示的话，作者又分不清是挂件坏了还是没声明对。
- **统计**：最多显示前 4 项。首页上的统计是概要，要看全的链到插件页面。
- **Markdown**：`#` 从三级标题开始（挂件的标题是二级）；代码块带复制按钮，同插件页面。

位置：
- 用户中心首页：公告下面、外置登录的快速配置上面。插件的提醒比快速配置和积分记录更需要被看到，但不该挤到角色展台和签到前面。
- 后台概览：站点的几个数字下面、最近的管理操作上面。

排列：
- 插件的挂件放在一起，插不进核心内容的中间。按插件 id 排，同一插件内按声明的顺序。
- 大屏两列、窄屏一列；个数是奇数时，最后一个占满一行。
- 每个挂件是一个 `<section>`：像素字的二级标题（同首页上的其他区块），右边是链接，下面一块 Panel。统计在 Panel 里排成格子，Markdown 直接放在 Panel 里。
- 不显示插件名：标题由插件写，"这个插件会做什么"里列着它放了哪些挂件。

### 插槽和运行时组件

ADR-0011 定了运行时组件的插槽列表（`SlotName`）和每个插槽传入的 props 是公开 API。这份 ADR 的 `SlotName` 就是那份列表：以后开放 `ui.script` 时，运行时组件放进同一批插槽，不另起一套插槽名。两个首页插槽没有 props。新增插槽是次版本，删除或改名是大版本。

### SDK

- 新类型 `SlotName`、`WidgetView`、`WidgetContribution`；`UiContributions` 多一项 `widgets`。
- type-tests：插槽拼错、表格放进挂件、权限没声明都编译失败。
- 构建命令把 `widgets` 原样写进 manifest；plugin host 和安装时的 schema 检查它。
- 作者文档的界面一页加"挂件"一节；从 BS 迁移的一页里"插槽"一行改写。
- 附 changeset，作为 `1.0.0-rc.7` 发布。1.0 之前加进来，1.0 起的核心都认得 `widgets`，插件不用为它提高 `api`。装在旧的核心（SDK rc.6 及以前）上时，manifest 检查会报"ui 里没有 widgets 这一项"。

### 参考插件

- **分享注册链接**：用户中心首页的挂件，Markdown。写明经链接注册一人各得几分，奖励有次数上限时写还剩几次；给出最新的一条链接（代码块，带复制按钮）和经链接注册了几人；还没有链接时提示去生成。链到"分享注册"页。分享人和新用户都不得分时返回 204：没有奖励的话，不必占首页的位置。
- **邀请码**：后台概览的挂件，统计：可用、已用、已过期的个数。要求权限 `manage`，链到邀请码页。

### 测试

- SDK：type-tests；api-extractor 报告。
- plugin host 和构建命令：`widgets` 的校验（名字、重复、个数、插槽、视图种类、链接的页面和区域、权限、路径）；manifest 的 schema。
- 核心：路由调用的限时参数；挂件按插槽、身份和权限筛选。
- 参考插件：挂件路由的几种情况（有没有链接、204、统计的个数）。
- e2e：分享注册链接启用后，用户中心首页出现挂件，生成链接后挂件里是这条链接、带复制按钮；邀请码启用后后台概览出现统计，链接回邀请码页；"这个插件会做什么"列出挂件；停用后都消失。

不加迁移。

### 落地顺序

一个 `feat/plugin-widgets` 分支，按顺序提交，做完再提 PR（ADR-0047：改了 SDK 公开 API）：

1. 这份 ADR；
2. SDK、构建命令、plugin host、type-tests、作者文档、changeset；
3. 核心：路由调用的限时、两个首页的挂件、"这个插件会做什么"和命令行、文案；
4. 参考插件、e2e；DESIGN.md §11、PROGRESS.md。

## 后果

- SDK 1.0 的公开面多了 `widgets`、`SlotName` 的两个值和 `WidgetView`。插槽名冻住以后，首页改版时这两个位置要一直留着。
- 插件能在核心的页面上占位置了。观感照旧由核心决定（DESIGN.md §11），但首页上有多少东西取决于装了哪些插件；每个插件在每个插槽最多两个挂件，限住了上限。
- 打开首页多了几次插件调用。插件出问题时首页最多慢 3 秒；host 不可用时，挂件都显示"没能加载"。
- 以后的运行时组件放进同一批插槽，挂件的 `view` 多一种，或者另加一个字段。
- 挂件的 `name` 以后可以给站长隐藏挂件、自定义 CSS 当钩子用；现在还不对外承诺。

## 考虑过的其他方案

- **照草案的五个插槽一次开齐**：挂在对象上的三个要先定上下文和可见性，又没有参考插件在用。冻进 1.0 以后就只能加、不能改。
- **插槽只留给运行时组件，声明式的只有页面**：插件想在首页说一句话，就得写 React、申请 `ui.script`，安装时还要醒目提示"以当前用户的身份执行代码"。
- **挂件里放表格和表单**：首页放不下分页和搜索，一页上还会有几个互相独立的表单。要操作的链到插件页面。
- **每个挂件一层 Suspense，分块流式**：页面不用等插件，但骨架换成内容时下面的内容会跳，204 的挂件会塌掉。插件路由在本机，正常情况下等的时间可以忽略，慢的插件由 3 秒的期限兜底。
- **在浏览器里水合之后再取数据**：要写客户端代码和骨架，和页面的数据源是两套做法，首屏还多一次往返。
- **失败时整个挂件不显示**：作者看不出挂件坏了，会以为是声明错了；204 已经给了插件主动不显示的办法。
- **链接写在 Markdown 里**：统计视图没有地方写；页面的地址写死在插件里，核心以后不能改。
- **按插槽分组声明**（`widgets: { 'user.dashboard': [...] }`）：一个挂件就是一条声明，插槽是它的一个属性，和 `nav` 的 `area` 是同一种写法。
