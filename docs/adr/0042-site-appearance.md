# ADR-0042 站点外观：站长上传方形的站点标志和站点图标，只收 PNG，重新编码后按像素 hash 存；图标没传时用标志；默认图标挪出 Next 的文件约定

- 状态：已采纳（站点的 CSP 由 ADR-0053 落地，统计和广告脚本、自定义 CSS 不再等它）
- 日期：2026-10-21
- 补充 ADR-0032：做它"不做"里推迟的自定义站点图标，另加自定义标志；页脚里的图片按一行文字的高度显示
- 取代 ADR-0032 里 favicon 按 Next 的文件约定放置、不读站点设置的部分
- 补充 ADR-0028：设置表单多一种图片控件，只给核心的设置项用

## 背景

ADR-0032 推迟了自定义站点图标（BS 的 `favicon_url`），留给以后的"站点外观"（上传站点图片）。现状：
- 标志是内置的像素图形（折起来的头），颜色取 token，站点名用像素字体写在旁边。用在页头、页脚、登录注册页，以及安装向导和维护页的全屏页。
- 站点图标是 `pnpm design:sync` 生成的三个静态文件，按 Next 的文件约定放在 `apps/web/app/`：`icon.svg`、`favicon.ico`、`apple-icon.png`。
- 页脚的备案号已经能填：`site.footer`（Markdown，ADR-0032）。
- 设置页的表单由注册表生成（ADR-0028）。控件有开关、数字、文本、Markdown、选项、多行、对象和机密，没有上传文件的。
- 材质已经有一条图片管线（ADR-0008、ADR-0025）：纯 JS 的 PNG 解码、图像 worker 池、`encodeTexturePng`、像素 hash。

BS 里相关的：
- `favicon_url`：一个地址，默认 `app/favicon.ico`，站长一般填 BS 公开目录下的相对路径。不导入，报告里列出（ADR-0032）。
- 没有上传 logo 的设置，导航栏左上角写站点名。想换成自己的图，只能改 `custom_css` 或主题。
- `navbar_color`、`sidebar_color`：选配色，见"不做"。

还没定的：收什么格式和尺寸、文件存在哪、标志替换哪一部分、`favicon.ico` 怎么跟着换、后台怎么上传。

## 决定

### 范围

这次做：
- 新设置项：站点标志 `site.logo`、站点图标 `site.favicon`；
- 设置表单的图片控件和上传接口；
- 站点图片的存储、公开地址和清理孤儿文件的定时任务；
- 根布局的图标 `<link>` 和 `/favicon.ico` 按设置走；
- Logo 组件显示上传的图；
- 页脚 Markdown 里的图片按一行文字的高度显示。

不做：
- 主题切换（BS 的 `navbar_color`、`sidebar_color` 选的是 AdminLTE 的配色）：DESIGN.md §2.3 的备选主题不只是颜色，高对比还改了边框和圆角，洋红要先挪危险色；每个主题都要过对比度检查，截图基线跟着成倍增加。另写 ADR。
- 统计和广告脚本、自定义 CSS：和站点的 CSP 一起做（PROGRESS.md）。先放开脚本再加 CSP，会把站长已经填好的脚本弄坏。
- 首页背景图、Open Graph 预览图：ADR-0032 的决定不变。预览图要绝对地址（`metadataBase`），以后和它一起考虑用不用标志。
- 暗色模式另传一张标志：见"后果"。
- 插件的设置用图片控件：插件 API 不变。

### 新设置项

都在 `site` 分区。值是图片的像素 hash（64 位小写十六进制），`null` 表示用默认：

| 键 | 默认值 | 用途 |
|---|---|---|
| `site.logo` | `null` | 替换标志的图形 |
| `site.favicon` | `null` | 浏览器标签、书签和主屏幕上的图标；没传时用 `site.logo`，也没有时用默认图标 |

图标没传时用标志：多数站长手里只有一张方形的图，传一次两处都换掉。只想换图标的，单传图标即可。

### 收什么图

两个设置项规则相同：
- 只收 PNG，文件不超过 1 MiB。SVG 能带脚本，要清洗或单独的沙箱响应头，第一版不收；JPEG、WebP、ICO 没有现成的纯 JS 解码器（ADR-0008），任何图片工具都能导出 PNG。
- 正方形，边长 16 到 512 像素。标志替换的是方形的图形（见"标志"），浏览器图标也是方形。
- 边长不到 64 的当作像素画：服务端按最近邻放大到不小于 64 的最小整数倍（16 → 64，24 → 72，32 → 64，48 → 96）。Minecraft 站点常见 16×16 的像素画图标，原样存下来，到了页头的 32px 和高分屏上是浏览器平滑放大，会糊。
- 解码以后重新编码（`encodeTexturePng`）再存：PNG 里的其他块（文本、色彩配置、APNG 的后续帧）都去掉，存下来的只有像素。存储键是像素 hash，同一张图传两次是同一个文件。不变量 3 的"不重新编码"管的是材质；站点图片没有要保持的历史地址。
- 另存一份白底的，给 iOS 的主屏幕图标用：iOS 会把透明的部分填成黑色（ADR-0032 的 `apple-icon.png` 也是白底）。
- 解码在图像 worker 池里做，同材质上传。

错误码：`site_image_file_invalid`（不是 PNG、解码不了、超过 1 MiB）；`site_image_size_invalid`，带宽高（不是正方形，或者边长超出范围）。

### 存储和公开地址

- 单独一个存储，不和材质、插件包共用：本地驱动放在 `<数据目录>/site-images`。材质的孤儿回收按材质表判断引用（ADR-0029），放在一起会被当成孤儿删掉。多实例部署时和材质一样要共享存储（ADR-0002）。部署文档让站长备份整个数据目录，不用改。
- 文件名是 `<hash>.png`，白底的是 `<hash>.opaque.png`。
- 公开地址 `/site-images/<hash>.png`、`/site-images/<hash>.opaque.png`，由 Hono 返回，加进 `next.config.ts` 的 rewrite 和 `proxy.ts` 的 `HONO_PATHS`（两处的范围要一致）。响应头：`Content-Type: image/png`、`X-Content-Type-Options: nosniff`、`Cache-Control: public, max-age=31536000, immutable`。换了图就是新地址，可以长期缓存。
- 文件在存储里就返回，不查设置：刚上传、还没保存的图要能在表单里预览。
- 维护期间照常返回：只读存储，不碰数据库。

### 上传和保存

- 上传：`POST /api/admin/site-images`，multipart，一个文件，要 `settings.manage`（超级管理员）。处理完写进存储，返回 hash。这一步不改设置。
- 保存：照常走设置表单的保存（`updateSettings`），值是 hash。事务之前核对存储里有这个文件，没有就当作这个字段的值无效；事务里不读存储，以后的共享存储是网络请求（AGENTS.md"已知的坑"）。
- 审计照常记 `setting.update`，带前后两个 hash。
- 恢复默认：控件上的"恢复默认"把值改成 `null`，同样要保存。

先上传、再保存，和同一页的其他字段一样能预览、能放弃。放弃的图留在存储里，由下面的定时任务清掉。

### 设置表单的图片控件

- 注册表的 schema 带 `contentMediaType: 'image/png'` 时生成图片控件（新组件 ImageInput）：当前的图按实际用到的几个尺寸画在棋盘格上（标志 64、32、24，图标 64、32、16），透明的部分看得出来；旁边是"上传"和"恢复默认"两个按钮，下面写尺寸要求。图片也可以拖到预览上。没设时显示默认的图形；站点图标没设、站点标志设了时，写明"跟着站点标志"。上传失败的错误显示在字段下面。
- 只认核心的设置项。插件设置的控件推导在 `plugin-host` 里，和构建命令共用；核心在外面包一层，认出图片控件，其余的交给它。插件的 schema 带这个媒体类型时照旧没有控件，插件 API 不变。
- 审计日志里写 hash 的前 8 位，`null` 写"默认图形"。
- 标签和说明照常写在 `admin.settings.fields` 下。

### 清理

新定时任务 `core:site-image-sweep`，每周一次，和材质的孤儿回收一样：列出存储里的文件，删掉当前 `site.logo`、`site.favicon` 都没引用、修改时间在 24 小时以前的。24 小时是给"上传了、还没保存"的表单留的；超过了再保存，核对不到文件，重新上传即可。

浏览器和 CDN 里缓存着的旧图会一直用到过期，但页面上早就换成新地址了。

导入 BS 不动这两个设置项：导入器只替换它自己写的那些键（`IMPORTED_SETTING_KEYS`，ADR-0031），站点标志和图标导入后照旧。

### 标志

- Logo 组件加一个可选的 `image`（图片地址）。给了就用 `<img>` 替换像素图形，尺寸不变（页头 32px，页脚 24px）；`alt` 留空，旁边已经写着站点名。站点名照旧用像素字体。不经过 `next/image`（不变量 8）。
- 不加 `image-rendering: pixelated`：上传的图多数不是像素画，非整数倍缩小时，最近邻会丢细节。像素画上传时已经放大到 64 以上（见"收什么图"）。DESIGN.md §5 的整数倍规则管材质和内置图形，不管上传的标志。
- 页头、页脚、登录注册页、安装向导和维护页的全屏页都用 `site.logo`。安装之前没有设置，向导里自然是内置图形；导入不动站点标志，`/site-images/` 维护期间也照常返回，维护页照旧显示它。
- DESIGN.md 的"标志"一行和组件清单补上；Logo 加一个带图的 story 和截图基线。

### 站点图标

Next 的文件约定里，`app/favicon.ico` 的 `<link>` 总排在最前面，metadata 的 `icons` 换不掉它；设了 `icons` 以后，`icon.svg`、`apple-icon.png` 的文件约定反而不再输出（Next 的 `resolve-metadata`）。所以：
- 根布局的 `generateMetadata` 总是自己写 `icons`：
  - 有自定义图标（`site.favicon`，没有就用 `site.logo`）：`icon` 是 `/site-images/<hash>.png`，`apple` 是白底的那份；
  - 没有：默认的 `favicon.ico`、`icon.svg` 和 `apple-icon.png`。
- 默认的三个文件照旧由 `pnpm design:sync` 生成、测试守着，但挪出 Next 的文件约定，放进 `apps/web/public/`，地址不变。Next 给 public 的文件加 `max-age=0`，浏览器每次都会核对，升级后改了 token 也拿得到新的，所以地址不带内容 hash。
- `/favicon.ico` 改成动态的，在 `proxy.ts` 里处理：有自定义图标时 302 到 `/site-images/<hash>.png`（`Cache-Control: no-cache`，换了图立即生效），没有时交给 public 里默认的那份。读不到设置（数据库不可用）时也用默认的；维护期间照旧跳转。页面上有 `<link rel="icon">` 时浏览器一般不直接请求它，但 RSS 阅读器、链接预览这类工具会。站长换了图标，它们不该还看到 NextSkin 的图标。
- `icon.svg`、`apple-icon.png` 照旧不经过 `proxy.ts`：维护期间不会被换成维护页。

### 页脚的图片

公安备案（"X公网安备 …号"）要在号码前放它的图标。`site.footer` 是 Markdown，本来就能写图片（地址放行 http、https 和站内路径，ADR-0028），但图片现在按原尺寸显示、带圆角。页脚里的图片改成一行文字的高度，和文字垂直居中，不加圆角。公告和内容政策里的图片不变。

### 导入

规则不变：`favicon_url` 照旧不导入，不是默认值时在对账报告里列出（ADR-0032）。报告和 MIGRATION.md 的说法改成"到后台的站点设置里重新上传"。

## 后果

- 多一个存储目录和一个定时任务。多实例部署要和材质一样共享存储。
- 上传的标志只有一张，亮暗模式共用。深色的图在暗色模式下会看不清，站长可以传带浅色描边或底色的图。真有需要再加"暗色模式的标志"。
- 默认图标是 SVG，标签栏随亮暗切换；自定义的是 PNG，不切换。
- 重新编码去掉了色彩配置，带非 sRGB 配置的图（比如 macOS 导出的 Display P3）颜色会略有变化。
- 标志只能是方形图形，站点名照旧是文字。想用横幅式标志（图里自带站点名）的站长做不到，见"考虑过的其他方案"。
- 图标没传时跟着标志：只换了标志的站点，浏览器标签也跟着换。

## 考虑过的其他方案

- **横幅式标志**（一张图自带站点名，宽度不限，替换整个 Logo）：BS 没有这项，国内皮肤站常见的也是图标加文字。横幅在暗色模式下更容易看不清，几乎一定要再传一张暗色的；读屏器和窄屏还要另外处理站点名。
- **方形图标外加"不显示站点名"的开关**：开关一打开，就是横幅的那些问题。有人要再加。
- **上传即生效**（上传接口直接改设置，不经过表单的保存）：和同一页的其他字段不一致，也不能先预览再放弃。
- **单独一个后台页、手写上传表单**：ADR-0028 定了设置表单由注册表生成。验证码、邮件分区里的"测试"按钮是动作，不是设置项。
- **文件存进数据库**（设置的值放 base64，或者单独一张表）：每个页面都要读设置，几百 KB 的值拖慢设置查询，SQLite 的库文件也跟着变大。
- **和材质共用存储**：材质的孤儿回收会把它们删掉，见"存储和公开地址"。
- **收 SVG**：矢量图在任何尺寸都清晰，还能随亮暗切换；但 SVG 能带脚本，有人直接打开它的地址时，脚本在站点的源上运行。要清洗（引入 SVG 清洗库）或给响应加 `Content-Security-Policy: sandbox`，另做。
- **服务端缩放出几种尺寸**（16、32、48、180……）：要写一个缩小用的重采样器。浏览器缩小的效果已经够好，最大 512 也限住了文件大小。像素画的放大只要最近邻，很简单，所以只做放大。
- **`/favicon.ico` 直接返回 PNG 的内容**：浏览器认，但地址和内容类型对不上，也不能长期缓存。重定向到带 hash 的地址更清楚。
- **继续用文件约定，只在有自定义图标时写 `icons`**：换不掉 `favicon.ico` 的 `<link>`，页面上会同时挂着默认和自定义两个图标。
- **`app/favicon.ico/route.ts` 动态返回**：Next 把这个路径当作静态的 metadata 路由（`isStaticMetadataRoute`），行为不可靠。
- **默认图标改成静态导入**（`import ico from './favicon.ico'`，地址带内容 hash、可以长期缓存）：`/favicon.ico` 本身还得有一份，要么 public 里再放一份，要么在 `proxy.ts` 里导入静态资源再跳转，后者在 proxy 的打包里没有验证过。默认图标很少变，`max-age=0` 加核对就够了。
