# ADR-0023 个人资料和账号安全：改邮箱先确认新地址，删除账号走领域用例，添加通行密钥要求刚登录过

- 状态：已采纳（改邮箱确认链接的作废条件一条已被 ADR-0024 取代；第三方登录后的两步验证、没有密码的账号由 ADR-0034 补充；后台改邮箱、邮箱改动生效时作废找回密码链接、后台关两步验证和删通行密钥、收回账号、命令行找回由 ADR-0036 补充）
- 日期：2026-10-18

## 背景

ADR-0022 把个人资料留到了这一步，连同两步验证、通行密钥一起做。Better Auth 的两步验证和通行密钥插件已经接上（`auth/auth.ts`），表也建好了（迁移 0019、0020），但还没有页面：没有地方开启，登录页也不处理 `twoFactorRedirect`。

BS 6.0.2 的个人资料页（`UserController::handleProfile`）：
- 昵称：不能为空，没有别的规则；
- 密码：核对旧密码，新密码 8 到 32 位，改完退出登录；
- 邮箱：核对密码，新邮箱不能已被占用；立即生效，同时变回"未验证"，然后退出登录；
- 删除账号：核对密码，管理员不能删除自己；删掉名下的角色和用户本身，材质和衣柜留下，指向已经不存在的用户；
- 头像：从材质里选；
- 被封禁的用户进不了个人资料页。

BS 没有两步验证和通行密钥。

查 Better Auth 1.7.10 的源码：
- `/change-email` 不要求密码，有会话就行。邮箱的修改发生在它的 `/verify-email` 里，我们的事件写不进那个事务（ADR-0018 遇到过同样的问题）。没有配置邮件时用不了。
- `/delete-user` 只删它自己知道的表。删角色、发事件，以后还有扣回收藏数，都得放进它的钩子，钩子拿不到事务。
- `/change-password` 用我们配置的校验函数核对旧密码，从 BS 导入的密码格式也能用；可以同时退出其他会话。
- 两步验证：
  - 支持 TOTP 加备用码，可选邮件验证码；开启、关闭、重新生成备用码都要核对密码；
  - 登录时的挑战用 `consumeVerificationValue` 消费，备用码用带条件的 UPDATE 划掉，在 serial 下都只能用一次。ADR-0015 的补充只关掉了依赖 `reserveVerificationValue` 的能力，两步验证不受影响；
  - 同一个挑战最多试 5 次；同一账号连续失败 10 次，锁定 15 分钟。
- 通行密钥：
  - 用通行密钥登录直接签发会话，不经过两步验证；
  - 添加通行密钥不要求密码，只要求会话是"新鲜的"：`session.freshAge`，默认是会话创建后 1 天内。
- 钩子的顺序：配置里的 `hooks.after` 先于插件的钩子执行。开着两步验证时，`/sign-in/email` 先签发会话，两步验证插件的钩子再删掉它，改成返回 `twoFactorRedirect`。所以配置里的钩子看到的 `newSession`，不一定是最后留下来的会话。

## 决定

### 范围

这次做：
- 个人资料：昵称、界面语言、邮箱、删除账号；
- 登录与安全：密码、两步验证、通行密钥；
- 登录页：两步验证的第二步、用通行密钥登录。

不做：
- 头像：要从材质里选，随材质一起做；
- 登录设备列表：Better Auth 的会话列表接口要求新鲜会话，页面还得识别设备。"怀疑密码泄露"这个最常见的需要，改密码时退出其他设备已经能处理；
- 邮件验证码作为第二步，理由见"两步验证"；
- 第三方登录，以及 Yggdrasil Connect 的授权管理。

### 页面

- 个人资料是 `/user/profile`，登录与安全是 `/user/security`，都加进用户中心的导航（ADR-0022）。
- `/user/profile`：
  - 页首是账号概况：昵称、uid、邮箱和验证状态、注册时间。邮箱没有验证时，可以在这里重新发送验证邮件；
  - 昵称和语言在同一个表单里保存；
  - 邮箱单独一块，修改时要输入当前密码；
  - 最下面是删除账号。确认框写明后果（DESIGN.md §7）：名下几个角色、几个 OAuth 应用一起删除，积分清零，无法恢复。
- `/user/security`：
  - 页首是账号现在的保护状态：两步验证开没开、有几个通行密钥；
  - 改密码：旧密码、新密码；
  - 两步验证、通行密钥各一块，见下文。
- 登录页：`/sign-in/email` 返回 `twoFactorRedirect` 时，进入 `/sign-in/two-factor`，保留 `next`。这一页输入验证器上的 6 位数字，也可以改用备用码，可以勾选"这台设备 30 天内不再询问"。
- 被封禁的用户只看到封禁说明（ADR-0022），这次的领域用例都返回 `user_banned`。由 Better Auth 处理的操作（改密码、两步验证、通行密钥）不额外检查封禁：被封禁的用户看不到这些页面，这些操作也只影响这个账号自己。
- 个人资料和安全设置都不要求先验证邮箱，与 BS 相同。

### 接口

新的 REST 接口都认会话 Cookie（ADR-0022），个人资料的响应格式与 SDK 的 `PrivateUser` 相同：

| 接口 | 请求 | 成功响应 |
|---|---|---|
| `PATCH /api/user` | `{ nickname?, locale? }` | 200，个人资料 |
| `POST /api/user/email` | `{ email, password }` | 配置了邮件：202，`{ pendingEmail }`；没有：200，个人资料 |
| `POST /api/user/email/confirm` | `{ token }` | 200，`{ email }` |
| `DELETE /api/user` | `{ password }` | 200，同时清掉会话 Cookie |

- 密码不对返回 400 `password_incorrect`，错误挂在 `password` 字段上。
- 改密码、两步验证、通行密钥直接调用 Better Auth 的接口，不另包一层。Better Auth 的 `/change-email`、`/delete-user` 保持它默认的关闭状态，并加进 `disabledPaths`，写明由领域用例代替。

### 昵称和语言

- 昵称去掉首尾空白后 1 到 255 个字符，与注册时相同（ADR-0018），不要求唯一。
- 语言只能选受支持的语言（ADR-0019），写进 `users.locale`。这就是 ADR-0019 说的"登录用户切换语言时，经领域用例写 `users.locale`"。
- 一条 UPDATE 改 `users`，同一事务里发 `user.profileUpdated`，`fields` 只列真正改了的字段。

### 改邮箱

- 先核对当前密码，用的是与登录相同的校验函数，包括从 BS 导入的格式。
- 新邮箱按注册的规则校验：格式、转小写、不能已被占用、邮箱域名的允许或禁止名单（`auth.registration.emailDomains`）。不查域名的话，用户可以先用允许的域名注册，再改成禁止的。
- 配置了邮件时，新地址要先确认：
  - 给新地址发一封确认邮件，链接 1 小时内有效：用户正在操作，会马上去收信。确认之前，登录和找回密码仍然用旧邮箱；
  - 链接打开的是一个页面（`/confirm-email`），点"确认"才提交。不在 GET 请求里改数据：有些邮件服务会预先打开邮件里的链接做安全扫描。确认不要求登录，用户可能在手机上打开邮件；
  - 令牌由领域层签发，不落库。载荷是 uid、旧邮箱、新邮箱和过期时间，用 HMAC 签名，密钥从 `NEXTSKIN_SECRET` 派生，派生参数与 Better Auth、设置加密都不同；
  - 确认时在一个事务里执行 `update users set email = 新邮箱, email_verified = true where id = ? and email = 旧邮箱`。改不到行，说明邮箱已经改过，链接作废，返回 400 `email_change_link_invalid`。所以同一个链接只能生效一次，同时发出的几个链接也只有先点的那个生效；
  - 新邮箱在这期间被别人注册了，由唯一索引兜底，返回 `email_taken`。PG 上唯一冲突会让整个事务作废，所以和 ADR-0022 的改名一样，等事务失败之后在事务外转换；
  - 改完给旧地址发一封通知，不带链接。账号被盗用时，原主人至少能知道。
- 没有配置邮件时与 BS 相同：立即修改，`email_verified` 变回 false。
- 修改的同一事务里发 `user.profileUpdated`（`fields: ['email']`）。不退出登录。

### 改密码

- 用 Better Auth 的 `/change-password`，前端总是传 `revokeOtherSessions: true`：其他设备全部退出，当前设备保持登录。BS 改完让当前设备也退出，没有必要。
- 新密码的长度范围与注册相同，8 到 128 位（ADR-0018）。
- 找回密码不会关掉两步验证，重设密码之后登录，仍然要过第二步。

### 删除账号

- 在事务外核对密码：scrypt 很耗 CPU，不能占着写锁（ADR-0018）。只要求密码，与 BS 相同：能拿到这个会话的人，已经过了两步验证。
- 事务里：
  1. 先锁住用户的行（`docs/schema.md` 的加锁顺序），再检查角色：
     - 管理员和超级管理员不能删除自己，返回 403 `admin_cannot_delete_self`。与 BS 相同，免得站点删得一个管理员都不剩；
     - 被封禁的用户返回 `user_banned`。否则删掉账号、再用同一个邮箱注册，就绕过了封禁；
  2. 逐个删除名下的角色，每个发一条 `player.deleted`。不退积分：积分随账号一起删除；
  3. 删除用户的行。Better Auth 的会话、密码、两步验证、通行密钥，OAuth 的客户端、令牌和授权记录，以及积分流水，都由外键级联删除；
  4. 发 `user.deleted`。
- 名下有 OAuth 应用时（从 BS 导入的应用可能属于普通用户），确认框里写明它们会一起删除，接入这些应用的第三方服务随即失效。
- 成功后清掉会话 Cookie，页面回到首页。

### 核对密码的接口要限流

- 改邮箱和删除账号都会核对密码。偷到会话 Cookie 的人可以借这两个接口猜密码，所以按用户限流：每 10 秒 3 次，与 Better Auth 给登录、改密码的默认限流相同，只是按用户计，不按 IP。
- 这是 REST 第一次需要限流，按 ADR-0002 的限流接口实现，默认存在进程内存里。

### 两步验证

- 只做验证器应用（TOTP）加备用码，不启用邮件验证码：邮箱本来就能用来找回密码，攻破邮箱的人两样都能拿到；而且会多一条依赖邮件送达的登录路径。
- 开启分三步：
  1. 输入当前密码，调用 `/two-factor/enable`，拿到 TOTP 地址和 10 个备用码。这时还没有生效；
  2. 页面显示二维码和可以手动输入的密钥。用户输入验证器上的 6 位数字，调用 `/two-factor/verify-totp`，通过之后才开启；
  3. 显示备用码，可以复制或下载成文本文件。只显示这一次。
- 关闭、重新生成备用码都要输入当前密码，这是 Better Auth 本来的要求。
- 页面显示还剩几个备用码：服务端调用 Better Auth 只能在服务端使用的 `viewBackupCodes`，只把数量交给页面，备用码本身不发给浏览器。
- 二维码在浏览器里用纯 JS 的库生成（ADR-0008）。每个模块画成整数个像素（DESIGN.md §5）。无论亮色还是暗色主题，都是浅色底、深色模块：不少扫码器认不出反色的二维码。
- "信任这台设备"用 Better Auth 的默认值：30 天，期间每次登录都会顺延。
- 丢了验证器、又丢了备用码，只能请管理员关掉两步验证。

### 通行密钥

- 用已经配置好的 `@better-auth/passkey`，rpID 是站点地址的主机名。
- 添加时用户给它起个名字，例如"工作电脑"，再由浏览器完成注册。列表显示名字、添加时间、是否在设备间同步（`backed_up`），可以改名、删除，删除前要确认。
- **添加要求刚登录过**：`session.freshAge` 从默认的 1 天改成 10 分钟。会话 Cookie 被偷走时，偷到的人不能悄悄给这个账号加一个自己的通行密钥；那样的话，之后改密码、退出其他设备也赶不走对方。
  - 会话超过 10 分钟时，页面说明原因，提供"重新登录"：先退出，再带着 `next=/user/security` 去登录页；
  - `freshAge` 还管着 Better Auth 的会话列表和解绑第三方账号，这两个现在都没有用到。
- 登录页加"用通行密钥登录"。浏览器支持时，邮箱输入框也提供通行密钥的自动填充。
- 用通行密钥登录不再要求两步验证。这是 Better Auth 的行为，也与 GitHub、Google 相同：通行密钥绑定站点，不会被钓鱼网站骗走。
- 浏览器端用 `@simplewebauthn/browser`，与服务端已经在用的 `@simplewebauthn/server` 出自同一个项目。

### 事件

- 昵称、语言、邮箱和删除账号由领域用例在事务里发事件，见上文。
- 改密码和找回密码由 Better Auth 完成，它的事务我们拿不到（ADR-0018）。`user.profileUpdated`（`fields: ['password']`）在 `/change-password`、`/reset-password` 成功之后，由 after 钩子另开一个事务写入。进程恰好在两次提交之间崩溃，会丢掉这一次事件。可以接受：密码已经改好了，事件只是通知。
- 两步验证和通行密钥的开关，SDK 里没有对应的事件，暂时不发。个人资料也没有拦截点（BS 有 `user_can_edit_profile` 过滤器），这次不加。需要时按插件 API 变更的流程加，这次插件 API 不变。

### 组件

新组件写进 `packages/ui`，配 story 和截图基线：
- Select：选语言；
- Badge："已开启""未验证"这类状态；
- QrCode：两步验证的二维码，按上文的像素规则渲染。

## 后果

- 不需要新迁移，用到的表都已经建好。
- `packages/email` 加两个模板：确认新邮箱、邮箱已更改的通知。邮件任务的载荷加上这两种模板，收件人本来就是单独的字段。
- `auth.ts` 改动：`session.freshAge` 改成 10 分钟；`disabledPaths` 加上 `/change-email`、`/delete-user`；改密码、找回密码之后发事件的 after 钩子。
- `user.loggedIn` 事件和 `user.login` 拦截器落地时，不能挂在 `/sign-in/email` 的 after 钩子上：配置里的钩子先于两步验证插件执行，看到的会话随后可能被删掉。要挂在真正签发会话的地方：没有开两步验证时的 `/sign-in/email`、`/two-factor/verify-totp`、`/two-factor/verify-backup-code`、`/passkey/verify-authentication`。
- 站点换了域名，所有通行密钥都会失效：WebAuthn 把凭据绑在域名上。后台修改站点地址时要提示这一点。
- 两步验证只保护网页登录。Yggdrasil 切片要决定：开了两步验证的用户，还能不能用 authserver（在启动器里填邮箱和密码）登录。在那之前，安全页不能说启动器登录也受保护。改密码时，authserver 的令牌也要失效。
- 后台的用户管理要能关掉某个用户的两步验证。
- 材质和衣柜落地时，删除账号的用例要补上：
  - 逐条移出衣柜，扣回收藏数（`docs/schema.md` 的 closet_items）；
  - 删除这个用户的私有材质：别人看不到它们，留着只占存储；
  - 公开材质保留，上传者置空（ADR-0015）。
- 在四种数据库上做请求级测试：
  - 登录时的挑战和备用码都只能用一次，同一个备用码并发提交只有一次成功；
  - 连续失败会锁定；
  - 改邮箱的确认链接只生效一次；
  - 删除账号时，该删的数据都删掉了。
- e2e 补上：改昵称；开启两步验证（测试里从 TOTP 地址算出验证码），退出后用两步验证登录；用 Chromium 的虚拟认证器添加通行密钥，再用它登录；删除账号。

## 考虑过的其他方案

- **用 Better Auth 的 `/change-email`**：不要求密码；修改发生在它的 `/verify-email` 里，事件写不进同一个事务；没有配置邮件时用不了。
- **改邮箱立即生效，之后再验证（BS 的做法）**：新地址还没证明是用户自己的，就成了登录名和找回密码的地址，输错一个字母就收不到找回密码的邮件。
- **用 Better Auth 的 `/delete-user`**：删角色、发事件、以后扣回收藏数，都要放进它的钩子，钩子拿不到事务。
- **邮件验证码作为第二步**：见"两步验证"。
- **添加通行密钥前输入密码**：Better Auth 生成注册参数的接口是 GET，没有地方放密码，只能自己包一层接口，再挡住原来的入口。缩短 `freshAge` 用现成的机制，效果差不多。
- **用通行密钥登录之后仍要过第二步**：多一步操作，安全上没有多少收益。
- **删除账号先进入冷静期，期间可以撤销**：要软删除，或者另外记录状态。ADR-0015 不做软删除，BS 也是立即删除。
