# 从 Blessing Skin 迁移到 NextSkin

适用于 Blessing Skin Server 6（BS 6.0.x）。导入只读旧库，旧站在整个过程中不会被修改，出问题时切回旧站就行。

有两种方式，做的是同一件事、生成同一份报告：

- **网页**：刚装好的站点打开 `/setup`（安装向导），选"从 Blessing Skin 导入"；已经在用的站点在后台的"数据迁移"里发起（只有超级管理员能用）。导入在服务里运行，期间站点处于维护状态：页面显示维护页，皮肤加载和外置登录返回 503。网页导入只支持单实例部署。
- **命令行**：`pnpm import:bs`。适合多实例部署、自动化脚本和超大的站点。命令行运行时 NextSkin 的服务要停着：导入会改写整个库，后台的材质回收也会删掉存储里没有记录的文件。导入器不检查服务是否在运行。

下面的步骤两种方式通用，命令行的写法和网页上对应的那一步写在一起。

## 准备

1. 一台能同时连到旧库和 NextSkin 数据库的机器。旧库可以和新库在同一台数据库服务器上。
2. 旧站的材质目录要能被 NextSkin 进程直接读到：同一台机器，或者把旧站的目录挂载进容器。默认在旧站的 `storage/textures`，`.env` 的 `TEXTURES_DIR` 可以改。旧站的 `FS_DRIVER` 不是 `local`（材质在对象存储里）时，先同步到本地目录。
3. 旧站的 `.env`：导入器从里面读数据库连接、表前缀（`DB_PREFIX`）、密码算法（`PWD_METHOD`）、盐（`SALT`）和材质目录。没有 `.env` 时，密码算法按 BS 的默认 `BCRYPT`；旧库里有十六进制摘要的密码时会停下来，要你提供 `.env`。
4. 旧站的时区：BS 写死在 `config/app.php`，默认 `Asia/Shanghai`。改过的话在表单的“时区”里填（命令行用 `--timezone`），否则所有时间都会错。

## 步骤

### 0. 安装码（只在安装向导里）

服务第一次启动、站点还没有初始化时，会在数据目录（`NEXTSKIN_DATA_DIR`，默认 `data`）生成 `setup-code` 文件，只有运行服务的用户能读；日志里只写它的位置。打开 `/setup` 先输入这个安装码：公网上刚装好的站点谁都能打开向导，安装码证明你是服主。安装完成（"新站"建好，或者导入成功）后这个文件会被删除，`/setup` 之后一律 404。

### 1. 试跑

网页上：上传或粘贴旧站的 `.env`，检查连接和材质目录，然后"开始试跑"。命令行：

```bash
pnpm import:bs -- --bs-env /srv/blessing-skin/.env --dry-run
```

- 试跑完整跑一遍、生成报告，最后回滚，不复制文件。报告与真正导入时的完全相同，也能用来估计停机时间：大站的时间主要花在解码材质文件上。
- 网页上直接显示报告，可以下载 Markdown；后台的"数据迁移"列出历次运行的报告。命令行的报告默认写在 NextSkin 数据目录下的 `import-<时间>.md`，也可以用 `--report` 指定，旁边的 `.uuids.csv` 列出每个角色的 UUID 和来源（映射表、指定、离线算法、随机），切换之前可以和游戏服务器上的数据核对。
- 网页上填的数据库密码和盐只在这次运行的内存里，不会保存；后台再次导入时，表单预填上一次的非机密项。
- 数据库连接也可以用 `--from mysql://用户:密码@主机:端口/库名` 指定，但命令行参数在进程列表里看得见，推荐写在 `.env` 里。盐不能从命令行传，只从 `.env` 或环境变量 `BS_SALT` 读。
- 迁移时常常换了域名或端口：用 `--site-url https://新地址` 覆盖旧站的站点地址。

### 2. 处理停止类问题

报告开头列出全部停止类问题，每一条都写着在旧站怎么处理。处理完重新试跑，直到没有为止。常见的有：

- **邮箱重复**：转小写、去掉首尾空格之后相同的邮箱。在旧站修改其中的邮箱，或者合并账号。
- **角色名只差大小写**：NextSkin 里角色名不区分大小写地唯一。在旧站给其中的角色改名。
- **UUID 冲突**：同一个角色在 `uuid` 表里有几个不同的值，或者两个角色得到同一个 UUID。在旧站修正 `uuid` 表，或者写一个指定文件：

  ```json
  { "12": "0f8d2c4b6a1e4f3d8c7b9a6e5d4c3b2a" }
  ```

  键是角色的 pid，值是 UUID（带不带连字符都可以），用 `--uuid-overrides 文件` 传入。网页上，一个角色在 uuid 表里有几个值时，直接在报告里这条问题的下面选一个，再重新试跑。**UUID 一变，游戏服务器上这个玩家的背包、领地、权限就全对不上了**：选游戏服务器上已经在用的那个值。

报告里还有不会阻止导入、但值得看一眼的内容：缺失或无法解码的材质文件（引用它们的材质被跳过）、取了边界值或没有导入的设置、认不出的表（其他插件的数据，没有迁移）。

### 3. 停掉旧站，最终同步

最后一次导入时旧站必须停止服务：试跑读的是旧库某一时刻的快照，材质文件却不在这个快照里，同步期间的上传可能只导入了一半。

```bash
pnpm import:bs -- --bs-env /srv/blessing-skin/.env --replace
```

- 每次运行都从旧库重新导入全部数据，结果与旧库当时的状态一致，包括旧库里删掉的数据。所以重跑没有"合并"的问题，停机时间等于一次完整导入的时间（材质文件的复制除外：存储里已经有、大小相同的不再复制，像素 hash 也沿用上一次的，不再解码）。
- 目标库已经有上一次导入的数据时，要加 `--replace`（网页上在"确认"这一步勾选）。
- 导入器发现上一次导入之后新站产生了数据（有人登录过、启动器登录过、签到、上传、注册），或者目标库有数据却从没导入过，会停下来列出这些数据。这时新站多半已经在用，再导入会冲掉玩家在新站的操作；确实要删除时再加 `--force`（网页上再勾选一次"删除新站的数据"）。
- 从后台发起时，导入替换了全部用户，你的登录也会失效：完成后用旧站的账号登录。

命令行的退出码：0 成功；1 有停止类问题，目标库没有改动；2 参数错误、连不上数据库或运行失败，目标库同样没有改动。运行中按 Ctrl+C 会取消并回滚；网页上点"取消导入"也一样。服务在网页导入中途退出时，数据库自己回滚，下次启动把这次运行标为失败。

### 4. 切换

启动 NextSkin，把域名指过来。用旧站的账号登录：密码原样导入，第一次登录时换成新的哈希算法。

## 迁移之后有什么不同

- **启动器要重新登录**：BS 的 Yggdrasil 令牌存在缓存里，没法导入。旧的 OAuth 令牌也全部作废，第三方应用的 `client_id` 和密钥不变，用户重新授权一次即可。
- **改名不再换 UUID**：BS 在离线算法下角色改名会换成新名字的离线 UUID，NextSkin 创建角色时分配 UUID，之后永远不变。
- **按名字查角色只忽略大小写**，不再像 BS 在 MySQL 上那样忽略重音（`Rene` 查不到 `René`）。BS 跑在 SQLite 上时区分大小写，迁移后不再区分。
- **公告和内容政策里的原始 HTML 不再显示**，只渲染 Markdown。报告里列出了含 HTML 的设置。
- **页脚的版权文字要重新填**：BS 的版权文字是原始 HTML，没有导入。报告里列出了原文，把它改写成 Markdown 填进后台“站点”里的“页脚文字”，备案号写成 `[京ICP备12345678号](https://beian.miit.gov.cn/)`（ADR-0032）。
- **首页换成了领奖台**：首页背景图、站点图标、导航栏颜色、自定义 CSS 和 JavaScript、`meta_extras` 都没有对应的设置，报告里列出了旧站改过的这些项。站点描述和 meta keywords 照常导入；meta description 就用站点描述。
- **上传奖励、被收藏奖励不再发放**，私有材质的状态码、自动删除无效材质等设置没有对应的功能，报告里列出了旧站改过的这些设置。
- **其他插件的数据**（例如 mojang-verification）没有迁移，报告的"认不出的表"列出了它们和行数。texture-description 的材质描述照常导入。
- 回滚：切回旧站即可，旧库没有被写过。但切换之后在新站产生的数据不会回到旧站，回滚只在切换后很短的时间内是无损的。
